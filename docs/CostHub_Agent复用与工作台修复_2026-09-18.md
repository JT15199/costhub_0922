# CostHub Agent 复用判断与改造方案

日期：2026-09-18。基于当前工作区源码和已安装 Pi 0.84.4；本轮没有改变 Agent 执行链，也未实测公司电脑的 27B 模型。

## 结论

可以复用成熟 Agent 的执行循环，而且 CostHub 已经这样做。建议继续使用 Pi，收敛外围自定义逻辑，不再另建一套 Agent。可以统一工具开始/结果、取消、补充指令、会话恢复的交互语义；不能只靠换框架保证相同回答质量和响应时间，模型、量化、推理模板、上下文及机器速度都影响结果。

目前不是“没有成熟 Agent”，而是成熟内核外仍叠加了兼容路径和多套任务指引。直接再包一层 CLI 会多出进程、会话和权限同步问题。

这些是代码路径观察，不是当前 27B 实际请求的性能剖析。

## 推荐实施顺序

### 1. 统一原生入口，先消除行为差异

对已经通过原生工具自检的配置，坚持单一 Pi 路径。将兼容模式作为明确的旧模型选项，不在同一会话内隐式更换协议。拆出原生专用的简短系统提示，保留安全要求、金额口径和缺失数据规则；业务流程说明放到相关工具描述或按需 Skill，删除重复协议说明。

验收：项目单价最高、数量乘单价贡献最高、按模块汇总三个问题，均直接进入 BOM 聚合工具，不先全量列项目、不分页扫描或再调用计算器。项目歧义和缺失价格必须保留澄清及未知状态。

### 2. 给每类任务一个明确工具入口

项目成本沿用 query_project_bom 的 rank / summary / group；表格分析统一到 analyze_spreadsheet 的 inspect / calculate，模型识别列与口径，程序计算；read 保留查看文本及具体异常证据的用途。附件预读和 Skills 提示随之统一，避免先预读、又全文读、再计算。

不要立即删除 read_excel：先核对导入、导出、旧会话和交互选文件的调用方，再迁移兼容层。业务工具结果只返回所需摘要、缺失项、来源及产物位置；完整行留在本地文件，可按需读取。

验收：万行 Excel 总额/Top N 不随行数增加模型请求轮数；总额、排序和导出回读一致。缺失价格不能变零，未选定金额口径不能猜。

### 3. 统一事件和持久化，随后再优化并发

由 Pi 的事件驱动统一状态：准备、思考、调用工具、等待用户、完成、取消、失败。模型结束、工具结束和保存结束的语义一致；失败不能显示成功，输出中断不能伪装完成。先测量每轮保存耗时、请求 token、工具耗时与模型首字/总耗时。

保持有副作用工具串行。若独立只读批量任务确有等待瓶颈，再把 pending 改为按 tool_call_id 的执行记录并验证恢复，然后允许明确标为安全的只读工具并行。不能仅把 sequential 改成 parallel。

验收：执行中补充要求、取消、切换会话、退出重开都不重复写入；结果未知时明确要求核对；同一操作只展示一次开始和结果。

### 4. 用同一模型做对照，才能谈体验一致

同一 llama.cpp 服务、同一模型与模板、同一上下文设置，对比精简 Pi 样例和 CostHub：固定一组只读业务工具及合成数据，分别测首个工具调用耗时、工具调用次数、输入输出 token、最终答案耗时与正确率。

若精简 Pi 同样慢，优先处理模型服务配置或硬件瓶颈；若 CostHub 多轮或提示更大，继续删掉宿主层的重复流程。没有这组对照，不能声称“搬来就一样快”。不用把公司数据带出来；测试可在目标电脑本地运行，只显示统计。

## 为什么不整包搬 CLI

Pi 官方把 Agent runtime、模型接口、coding CLI 和终端 UI 分为不同包。CostHub 需要的是运行时与工具协议，已有 React 界面及 Rust 执行边界；CLI 的终端界面不会自动变成 CostHub 的交互。完整 CLI/SDK 接入还要验证运行时分发、进程生命周期、SQLite 工具桥接、恢复记录迁移和 Windows 免安装部署。

更关键的是，上游 Pi 明确不自带文件、进程、网络和凭据的权限限制。CostHub 的工具白名单、业务写入确认、任务目录约束、隔离脚本与受控联网不能因此移除。成熟执行框架不替代业务安全边界。

来源：[Pi 官方仓库：包划分与权限说明](https://github.com/earendil-works/pi)。本地接口依据已安装版本的 node_modules/@earendil-works/pi-agent-core/README.md；避免把网上新接口当成当前可用接口。

## 本轮 UI 交付

- 年份从装饰文字变成真实筛选，列出已有记录年份及当年；按选中年一起加载收益与目标，快速切换丢弃过期响应。
- 明细改为无填充背景的原生按钮，左右对齐；弹窗标题带所选年份。
- 保留蓝色通透风格，进度条增加十分位刻度，环图减薄、阴影减轻，金额使用等宽数字。
- “实测数据”改为“按录入数据测算”，避免把单台降本乘年度发货量的测算当成已实现收益。
- 浏览器模拟数据验证六种尺寸、年份回调、明细弹窗和入口背景；不写正式数据库。

验证结果：前端生产构建通过；浏览器六种尺寸及年份/明细控件检查通过；Pi 宿主、BOM 重复调用和工具选择共 10 项测试通过。桌面发布首次尝试被正在运行的 target/release/costhub.exe 文件锁阻止，等待关闭应用后重新打包。
