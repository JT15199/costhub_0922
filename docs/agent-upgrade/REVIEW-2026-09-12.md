## 阻断项与最小返修

### 1. P1：压缩失败也提交删减后的上下文

位置：`src/ai/contextPolicy.ts:111-127`。

摘要超时、取消或 JSON 校验失败后，catch 仅生成错误说明或沿用旧摘要，随后仍返回“摘要 + 最近消息”，丢掉本轮尚未总结的前缀。代码注释称 lossless，但仅原始日志仍在磁盘不等于模型保留了用户约束。长任务会失去早期目标、限制和证据。

返修：失败不提交压缩结果；保留原上下文与旧 state，并停止本次超限请求或走可审计的分块压缩。不要继续把超限原文交给模型自动截断。补充真实生产函数的超时、取消、坏 JSON 回归，验证消息、约束和 state 不发生丢失。

### 2. P1：预算没包括系统提示/工具，摘要输入直接截字符

位置：`src/ai/contextPolicy.ts:76,102`，`src/ai/piRuntime.ts:378-393`。

触发压缩只计算 messages；实际请求还附带大段 systemPrompt 和工具 schema。摘要输入固定 `.slice(0, 50000)`，没有按有效窗口分块；8K 环境中 50,000 字符可能远超窗口。单个超长消息使 prefixEnd 为 0 时直接原样返回，也没有硬预算拦截。摘要成功后没有检查最终上下文是否仍超限。

返修：在最终请求组装处统一计算 system、动态 schema、消息与输出预留；摘要源也受同一预算约束，分块处理完整工具交互组。补充长中文、长单工具结果、大 schema 和摘要后仍超限案例，断言每个实际发出的请求都在预算内。

### 3. P1：通用产物请求被改成固定验收样例逻辑

位置：`src/ai/piRuntime.ts:46-128,285,360-362,472-526`。

只要文本出现“文件/报告/表格”等就进入 requestedArtifact 分支，初始隐藏 read_excel、write_excel 和发现工具；后续强制生成“报价对比”Excel。模型参数无效时，宿主按 `source_id/material` 列及 `A-R数字-` 编号重建 R1/R2 工作表，还按验收注入行的特定字符串过滤。它适配的是测试夹具，无法代表用户任意 CSV、任意字段、Markdown 报告或其他项目的自主处理能力。提到文件也不等于要求生成 Excel。

返修：移除运行时对夹具字段、项目编号和固定工作表的依赖。工具参数错误返回明确校验信息，让模型使用真实读取结果修正；保留正常工具发现。用完全不同字段名、项目名和任务类型的文件验收，包括“只阅读不要生成”、Markdown、CSV 合并、两份独立产物，不能继续通过新增关键词补丁过关。

### 4. P1：用户停止后可能进入新的恢复轮次

位置：`src/components/AiPanel.tsx:980-985`，`src/ai/piRuntime.ts:441-526`。

停止按钮 abort 当前 Agent，但外层 await 返回后仍检查空回答/产物并调用新的 agent.prompt；没有贯穿整次 run 的取消状态。Pi 的 abort 取消当前 activeRun，后续 prompt 可以开启新 run。生成文件任务尤其容易在用户停止后又启动恢复。

返修：使用整次任务的取消信号，所有恢复、压缩和工具前检查同一状态；内部看门狗与用户取消必须区分。测试在第一次工具前、工具后、压缩时、恢复前点击停止，断言不新增模型请求、不新增工具动作。

### 5. P1：所有模型与最终答复都强制 768 token、关闭思考

位置：`src/ai/piStream.ts:82-86`。

`think:false` 和 `num_predict: Math.min(...,768)` 无条件应用。不是仅对工具参数轮次做限制；复杂审价说明、长脚本和最终报告都会被截短，界面 deepThink 也无法控制实际传输。不能用 CPU 小模型测试的临时限额作为所有模型固定策略。

返修：按实际模型 profile 与剩余预算决定输出长度；明确工具轮与最终答复策略，并让用户思考设置与实际请求一致。测试请求参数，以及需要超过 768 token 的完整业务交付和截断后的合理处理。

### 6. P1：执行生命周期迁移未完成

位置：`src/components/AiPanel.tsx:738-761`，`src/ai/piRuntime.ts:376`；对照 `IMPLEMENTATION.md:69-89,323`。

当前仍由 React 组件直接调用 new Agent 并通过组件 refs/回调管理运行与持久化。源码未接入方案要求的 AgentHarness/Session 独立宿主，也未看到具有同等保证的 Worker 执行服务。原始事件和检查点是进步，但不能代替独立任务生命周期。

返修：先完成一个真实独立运行链，再接回现有简单 UI。验证关闭面板、导航、重建 UI 时任务状态不丢失；进程重启恢复到明确状态。不要仅为了名称替换 Agent 类，必须证明生命周期与恢复语义。

## 验收证据不足，不能算通过

1. `tests/agent-upgrade/restart-recovery.py` 自己创建表并写入固定状态，再用 Python 打开读取，只能证明 SQLite 持久化。它没有调用生产动作路径，不能证明写入恰好一次、崩溃窗口或恢复策略。需要生产动作在提交前/提交后/结果回写前分别注入故障，在隔离数据库复核。
2. `artifacts/agent-upgrade/20260912-e01-qwen3-v4/e01-real-evidence.json` 明确 `passed:false`，未生成真实文件；final24 文件由宿主样例修补后生成，仍不能作为通用能力通过证据。

4. 三次摘要生成不等于 E03 通过；必须证明完整任务经过三次压缩仍保留初始约束、后续修改、引用与文件要求。
