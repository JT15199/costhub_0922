## P1：压缩后的工作上下文没有成为后续运行状态

位置：`src/ai/piRuntime.ts:286-291`，`src/ai/contextPolicy.ts:43-46`；Pi 实现 `node_modules/@earendil-works/pi-agent-core/dist/agent-loop.js:177-193`。

`transformContext` 返回值只用于本次模型请求，Pi 不将其替换到 `agent.state.messages`。CostHub 将压缩结果存检查点，却在工具前、运行结束继续把未压缩的 Agent state 保存回去。后续压缩的 `buildCompactionSource` 又假定索引 0 已经是旧摘要，直接跳过第一条消息。这两个状态约定不一致，会重复摘要旧消息、使上下文压缩不能持久生效，并让原始首条要求依赖此前摘要保真。

本次可执行探针使用真实已安装 Agent：初始消息 ORIGINAL，用户追加 NEXT，transformContext 返回 COMPACTED，确定性 stream 返回 done。实际结果：

```json
{"request":["COMPACTED"],"agentState":["ORIGINAL","NEXT","done"]}
```

这验证的是 Pi 的真实执行语义，不是模型质量。现有直接把 `compactContext` 返回值传给下一次测试的方式，不能发现这个接线问题。

返修：在独立 Session 中明确区分不可变原始事件与可恢复的工作上下文；压缩提交后，后续轮次和重启必须从同一工作上下文继续。不要只改检查点，也不要为了缩短上下文删除原始日志。新增真实 Agent 多轮集成测试：连续三次压缩、一次工具调用、结束保存、恢复继续；断言送模型的上下文和持久化状态一致，原始历史另行完整保留。
