# CostHub 通用 Agent：实施设计与阶段指令

日期：2026-09-10。面向接手的 Luna。配套：README.md、PROGRESS.md、ACCEPTANCE.md。

## 0. 实施目标与完成定义

交付一个真正能做事的成本专业 Agent：用户用自然语言提出目标，它自主发现工具、读取文件与业务数据、执行计算/脚本、根据失败修正方案、按需询问、生成产物、自动压缩并保持任务连续，必要时在明确的数据边界内多轮咨询云端。不能只实现聊天皮肤、固定工作流或“计划一次后机械执行”。

完整交付必须包含：原生工具循环、任务持久化、长结果可检索、自动上下文压缩、取消/续做/重启恢复、受隔离的脚本执行、可打开的文件与图表、证据引用、脱敏云端协作、低干扰机会发现，以及真实 Qwen/桌面/便携验收。

通用能力的边界：用户提供或明确授权的文件、应用业务数据、受控公开检索、受隔离的 Python/Node 脚本、工作区产物。此次不要求复制所有竞品功能，如任意第三方桌面点击、邮件代发、插件商店、多个自主子 Agent；这些不影响本次通用执行闭环。不能以此边界为由省略沙箱、检索、文件、上下文或完整任务验收。

专业化放在工具语义、资料和 Skill 方法中，不写死“出现价格二字就只能查行情”。模型可以把报价、BOM、手账、历史版本、公开资料串联起来，也可以得出“证据不足”或“原先怀疑不成立”。

## 2. 用户使用逻辑：只保留一个主工作入口

### 2.1 默认界面

- 沿用全局 AI 对话面板，允许展开为宽工作区，不再新增一个独立且能力不同的 AI 页面。
- 顶部：任务标题、当前关联项目（可清除/切换）、历史任务入口；本地/云端协作状态用小标签。
- 底部：附件、输入框、发送/停止。高级菜单放模型、上下文诊断、执行权限、云端权限与预算。
- 旁侧或下方折叠区：任务进度、文件/图表。用户无需知道工具名、Skill 名、原生/文本协议区别。
- 空白时最多三个示例：“分析这份报价”“查找本项目机会”“整理谈价材料”。它们只是普通输入，不启动硬编码流水线。
- 已有会话历史可看，切项目/切页面不重置运行中的任务。项目绑定随会话保存，不能从当前页面猜一个项目去写库。

### 2.2 一次完整任务

1. 用户在项目中点“AI 查找机会”，或直接拖入报价并提问。系统附加项目 ID/附件引用，不复制整库到系统提示词。
2. Agent 简短说明将核对的内容；复杂任务生成少量可更新步骤，然后真正调用工具。
3. 工具活动显示“读取报价表 / 核对历史版本 / 计算差异”等短状态，可展开看参数、结果摘要、来源或错误。不能每轮清空先前展示的进展。
4. 出错则自行读错误、调整输入或脚本再试；不把同一次失败以相同参数循环执行。必要时给具体缺口。
5. 用户执行中发送补充，当前执行安全点接收 steer；“稍后做”放到队列。所有补充先持久化再确认收到。
6. 用户停止后模型请求与相关脚本都取消。后台回调带 runId 校验，旧结果不得写进新一轮 UI。
7. 快到上下文预算时显示一条“正在整理上下文”，自动整理后继续，历史聊天仍可查看，无需用户手动开新对话。
8. 结尾给结果、依据/局限和已生成文件。修改业务数据时先展示具体变更预览；没有授权不落库。文件产物可在授权工作区内直接生成。

### 2.3 最少但有效的确认

- 只读查询、任务目录读写、已授权隔离脚本：不用逐个确认。
- 业务写入：按真实改动批次确认一次，显示目标项目、字段/条数和覆盖/新增语义；禁止“是否允许工具 X”这种空确认。
- 云端：第一份出域包可预览；支持对当前任务的明确字段范围与预算授权，后续包仍逐次后端校验。
- 原始本机命令：保留单独明确授权，不能把它当隔离脚本失败的自动备用路径。
- 缺少必要业务信息时才 ask_user，给具体问题；不要求用户重复已经读到的信息。
- 不展示长篇内部推理作为“智慧”的替代。默认展示行动、证据、判断变化和结果；模型思考内容若保留，只在本地按供应商协议处理，不外发。

## 3. 目标架构：复用 Pi，拆开界面与执行生命周期

### 3.1 推荐结构与可接受替代

```text
React 对话/任务/产物视图
          │ 订阅事件、提交输入、确认/停止
Rust 任务与权限管理（SQLite、任务索引、进程、出域校验、工具写入账本）
          │ 私有管道 / stdio RPC，携带 taskId/runId/requestId
受信任 Pi 宿主（随包 Node + 打包后的 TS，复用 AgentHarness/Session）
          ├── 本地 Ollama 适配：请求走统一调度与后端网络出口
          ├── 工具目录 / 成本 Skill / 证据与上下文管理
          └── 工具执行请求交给 Rust broker
                    ├── 只读/业务写入工具（复用既有业务函数）
                    ├── 受隔离 Python/Node worker（不继承密钥和宿主管道）
                    └── 受控云端/公开检索
```

默认使用上述独立宿主，因为关闭 AI 面板、React 卸载或切页不应终止任务。Rust 保持拥有进程与任务锁，关闭整个应用时先取消并保存；本轮不要求应用退出后常驻继续执行。

P02 做小范围技术验证后，如现有 Pi Session/ExecutionEnv 可在专用 Web Worker 中提供完全相同的持久化、脱离组件生命周期、重建与取消保证，可以采用 Worker 降低改造成本，并在 PROGRESS 记录理由和全部通过的测试。不要把运行循环继续放在 React 组件内，然后声称已独立。

Node 宿主是受信任应用代码，不是沙箱。用户/模型生成的脚本只能进入另一个隔离进程。不要把模型输入作为宿主代码 eval，不向脚本透传 RPC 管道句柄或业务数据库连接。

### 3.2 复用而非复制业务代码

- 从 AiPanel 抽出不依赖 React 的调度、工具执行与事件适配。Tauri invoke/window/global 附件状态统一换成小范围 I/O 接口和 taskId 绑定的附件注册表。
- `getDb` 等 I/O 可通过受信任宿主到 Rust 私有 RPC 适配；已有业务函数继续执行参数化查询。不要把“任意 SQL”作为模型工具公开。
- 宿主启动只读打包程序，命令行参数不含密钥。通讯用父子进程专用管道，不增加向外监听的无鉴权 HTTP 服务。
- 模型调用统一经过一个调度入口；现有 autoAdvisor/autoInsight/对话/压缩不能各自抢占同一 GPU。
- 使用现有注册器挂载工具。每种工具只留一个语义与权限定义，不维护两份互相矛盾的 whitelist。

### 3.3 持久化最小模型

优先复用 Pi Session/JsonlSessionRepo，SQLite 维护原有会话 ID、标题、项目和运行状态索引；不要再造第二套完整对话日志。

每个任务拥有：完整原始事件记录（含工具调用/结果引用）、Pi 会话、TaskState、压缩记录、附件/证据/产物、动作账本。完整记录是事实来源；压缩后的模型输入只是可重建视图。

TaskState 至少记录：

```ts
// 设计字段，不要求照抄命名；任务事实与数据引用必须独立于自然语言摘要。
type TaskState = {
  version: number; taskId: string; projectId?: number;
  goal: string; userConstraints: { text: string; messageId: string; supersedes?: string }[];
  status: 'idle'|'running'|'compacting'|'waiting_user'|'waiting_approval'|'paused'|'completed'|'failed'|'interrupted';
  plan: { id: string; text: string; status: 'pending'|'running'|'done'|'blocked'; evidenceIds: string[] }[];
  verifiedFacts: { text: string; evidenceIds: string[] }[];
  openQuestions: string[]; rejectedHypotheses: { text: string; reason: string; evidenceIds: string[] }[];
  artifactIds: string[]; lastCommittedEventId: string;
};
```

授权由后端独立保存：任务、工具/字段范围、有效期、剩余调用/费用预算、撤销状态。不得从摘要或模型声称“用户已允许”中恢复权限。

TaskState 优先作为 Pi 的版本化 custom entry 保存，并用 SQLite 做可重建索引，不再平行维护一份无法对账的“真状态”。Pi `Session.appendCustomEntry`、SessionStorage/JsonlSessionRepo API 已在本地依赖中存在；验证 fsync、追加中断与末尾损坏恢复能力，不因有 JSONL 就假定原子耐久。动作账本与业务写入的原子性由 SQLite 负责，跨 JSONL/SQLite 不宣称全局事务。

迁移宿主不能绕过登录/锁定：当前 `src/db/core.ts` 的 dataLocked 是前端状态。新宿主与 Rust 业务入口必须验证后端登录会话/解锁状态，锁定后取消/阻止敏感查询并遮蔽受保护视图；不能用 rawDb 适配后让未登录宿主访问正式数据。任务目录也不能包含明文密钥。

工具状态：prepared → executing → succeeded / failed / cancelled / unknown。业务写入的 actionId 与写入结果在同一个 SQLite 事务中保存，重试同一 actionId 返回原结果。原生脚本/外部调用发生崩溃时可能 unknown，不能保证 exactly-once，也不能自动重跑。纯读工具可按声明重试。

持久化必须有 task/run 序号或乐观锁，取消后迟到消息不能覆盖状态。单任务单执行者；任务切换不共用全局附件、问题/确认 resolver。切页后仍可从持久化事件重建 UI。

## 4. 上下文与 24GB 显存：实施细则

### 4.1 先测实际模型，不能按参数量猜窗口

当前官方 `qwen3.8:27b` 标签页面列出 Q4_K_M、约 18GB 模型包并标注工具/思考能力；这是模型分发信息，不是本机实际显存占用或可稳定上下文的保证。见本文件末尾来源。

P01 读取配置中的真实 Ollama 地址与模型名称，查 `/api/version`、`/api/tags`、`/api/show`（用实际 model）、`/api/ps`，有 NVIDIA 工具则记录显存。记录 digest、量化、Ollama 版本、模型支持能力、实际 processor/offload 和 context_length；不导出 API key。

建议起测顺序：8K → 16K → 24K → 32K。默认候选 16K，只有真实长输入、工具任务、压缩和显存测试通过才选为有效配置；若 16K 不稳，8K 加更积极检索/压缩仍需过质量测试。不要盲开理论 256K，也不要把“模型元信息写 32768”当已经设置了 Ollama。

- 每次请求明确传 `options.num_ctx = effectiveContext`，Pi model.contextWindow 与之匹配。
- 主任务和摘要共用模型实例/窗口、串行调度，避免压缩又加载一份模型或另设窗口造成频繁重载。
- 评估 Flash Attention 和 q8_0 KV 缓存；是否支持/实际生效要查当前 Ollama。不得静默更改全局环境或重启用户服务。优先应用请求级可控设置；服务级实验记录具体变更，得到现有授权后才做。
- 并行模型请求默认 1，后台读数据库可以并发，本地推理不并发。不要擅自停止别的应用正在使用的模型。
- 分别记录冷启动、热启动、prefill、生成速度、峰值显存；不是只跑一句“你好”。

### 4.2 真 token 统计与预算

Rust `http_stream` 保留完成帧中的 `prompt_eval_count`、`eval_count`、load/prompt/eval/total duration、done_reason；前端/宿主适配到 Pi Usage，不再全部置 0。缓存计数缺失为 unknown 或文档规定值，不能伪造命中。流结束、截断、错误、取消只发一次最终状态；模型输出因长度结束不能当任务完成。

定义预算（单位 token）：

```text
C = 通过校准的实际上下文（例如 16384，不是固定值）
O = 本轮输出预留，普通工具任务初始 3072，长答案按预算调整
M = 模板/估计/视觉等安全余量，初始 max(1024, ceil(C*0.08))
B = C - O - M                         # 所有输入的上限
输入 = 系统+激活工具schema+用户约束+TaskState+历史摘要+近期完整轮次+检索证据+本轮输入
soft = floor(B*0.80)                  # 开始主动压缩/收回不用的工具
hard = B                              # 绝不发送超过上限的已知输入
整理后目标 = 不高于 B*0.60，避免每次发言都再次压缩
```

上述比例是初始工程参数，P08 根据实测修订并记录。O 包含模型可能占用的思考输出；不要在 16K 输入窗口再无条件预留/请求 16K 输出。

优先使用兼容的真实 tokenizer；没有就使用本地 Pi 估算并用实际 prompt_eval_count 保守校正。必须覆盖中文、JSON、代码、工具 schema，不得统一按“4 字符=1 token”。估算值 UI 标“估算”，图片 token 不能只用 base64 字符长度算；优先裁剪/按需读取，视觉任务单独校准。保留请求前估计和请求后实测便于发现服务端截断。

预算包含 system 和工具 schema，不能只统计聊天文本。工具目录默认仅短描述，按需激活少量 schema，完成阶段后可以释放不再需要的 schema。

### 4.3 三层上下文，完整历史不删除

1. **永久记录层**：完整会话事件、附件、原始工具结果、脚本和产物。保存在任务目录/既有数据库，不把所有内容每轮发送。
2. **任务记忆层**：用户目标、最新约束、已核实事实及来源、已排除假设、未完成工作、产物与动作状态。来源明确、可追溯，不靠一句模糊总结。
3. **工作上下文层**：任务记忆＋有来源的历史摘要＋近期完整交互＋这一步实际需要的证据。模型按需搜索/读取旧事件和结果全文。

不要为了这三层立刻引入向量数据库。优先既有 SQLite/FTS（可用才用）与精确字段/全文检索；关联项目、版本、附件、页/行、工具输出 ID。证明检索覆盖不足后再扩展，不先造 RAG 平台。

### 4.4 压缩触发、内容与一致性

在每次模型请求前计算预算；工具执行结果持久化后、下一次推理前可以压缩。先处理无损缩减（结果分页、旧图像引用、移除重复 schema），仍超过 soft 再调用摘要。不要在未返回的工具调用和结果中间切断。

优先接入 Pi AgentHarness 的自动 compaction、Session、retainedTail。核对当前库对单个长 turn 的切点和 tool call/result 配对；如不能满足，在适配层保留完整工具交互组，不改原始日志。不要照搬库默认 token 预留，它可能大于本机窗口。

**已核实的具体陷阱：** 当前 Pi 0.84.4 默认 `reserveTokens=16384`、`keepRecentTokens=20000`，不能直接用于 16K 窗口。其 `shouldCompact` 使用 `contextWindow-reserveTokens`，而摘要输出上限还与 reserveTokens 相关。必须把本应用的 soft/hard 策略与库参数分开映射并测试；例如 16K 起测可用 reserveTokens 4096、keepRecentTokens 2048，另在 soft 门槛主动调用 compact。实际摘要请求再预留预算，不能把这些示例当通用最优参数或忘记新 schema/图片的占用。摘要使用专用生成 profile 控制输出长度，但保持同一个已加载模型与 num_ctx。

摘要字段必须包含：目标、用户最新修订（关联原消息）、已完成动作/结果、事实与证据 ID、未决问题、已失败方案及原因、下一步、文件位置。权限与动作账本由确定性数据注入，只允许摘要引用，模型不能修改它们。源文件里的指令只能作为引用资料，不提升为用户指令。

摘要前后执行：

1. 持久化到稳定事件边界，记录 source range/hash 与 taskState revision；新的 steer 先排队落盘。
2. 使用专门“摘要”调用，只读文本、无工具权限、无云端、低输出预算。摘要任务不继续执行业务。
3. 压缩输入本身必须符合窗口。历史过长按完整交互组分批摘要，然后合并；不能把已经超限的全文再塞给同一个模型。复用 Pi 分段能力；缺失时补薄适配。
4. 检查必需字段、原消息/证据 ID 是否存在、路径有效、不能声称未成功动作已完成；用户约束和账本以结构化来源为准。
5. 以新压缩版本原子提交摘要＋保留尾部引用，旧日志不改；同时记录 tokensBefore/tokensAfter、来源范围、模型、失败重试。UI 展示真实估计/实测语义。
6. 加入摘要期间到达的新输入；按用户最新修订更新约束，再重新检查预算才继续。

保留至少最近完整用户交互和完整工具结果链，数量按 token 算，不按固定最后 16 条截取。一个 turn 太长时可整理已完成的前缀工具交互，保留本轮目标与最新链；不得出现无对应调用的 tool result。重要证据变成引用后提供 `search_history` / `read_evidence` 可找回全文。

### 4.5 压缩失败与边界情况

- 摘要生成失败：原状态不动，最多一次修复/重试；不将失败文本替代上下文。
- 持续失败但无损裁剪仍能满足 hard：保留结构化 TaskState＋可检索原文＋近期完整链，以明确降级状态续做；不能丢约束、权限、未决写入。不能容纳则暂停并显示具体原因，绝不让 Ollama 默默截掉前文。
- 用户单条输入就超限：保存原文为附件，分段检索；把用户明确要求单独保留，不能静默截掉末尾指令。
- 取消摘要：停止生成，不替换旧压缩版本；下次继续重新检查。
- 摘要内容有新“用户授权”或无来源金额：不采纳，保留原授权与事实；检查异常并提供可检索原文。
- 同一压缩世代不重复整理；使用阈值回落区间。主模型与摘要共享推理锁时避免重入死锁；摘要作为当前任务内部子操作使用同一个调度租约。

## 5. 通用工具与执行边界

### 5.1 工具目录

在现有 toolRegistry 上增加短目录与 `discover_tools(query, domains?)`，返回少量匹配工具的 schema，并在下一轮原生调用中激活；也能按领域列全目录，不能永远只截 Top N。discover 是提示匹配，不是新的安全判定。

基础常驻：工具发现、任务/文件列表、按范围读文件、全文/证据检索、ask_user、任务进度更新。业务工具根据需要加载；模型可以从“价格”任务发现 BOM 或手账工具，不靠用户换措辞。

动态 schema 变更必须在请求边界生效。未知工具返回可发现的目录提示；越权工具明确拒绝。参数类型支持布尔、数组、对象、枚举、必填、范围；现有嵌套 JSON 字符串逐项改成结构化参数或可靠解析，不把 boolean 转 string。

### 5.2 必须可用的通用能力

| 能力 | 最小真实实现 |
|---|---|
| 文件 list/read/search/write/edit | 路径规范化、行范围、分页、编码、二进制识别；edit 有旧内容/版本校验，不能盲覆盖 |
| CSV/XLSX | 复用 xlsx；列出工作表、读取范围/过滤、来源 sheet/row，数值类型与公式缓存明确；可写 xlsx/CSV |
| PDF/图片 | 复用 pdfjs/现有 OCR 或视觉入口；页码来源，扫描件需 OCR，低质量提取明确提醒 |
| Python/Node 执行 | 随包固定运行时、隔离进程、超时/取消、stdout/stderr、退出码、完整日志、可重复运行脚本 |
| 本地业务查询 | 现有工具支持准确项目 ID/版本、过滤分页、来源/数据缺失语义；不拿前 60 条无关记录代表全库 |
| 公开资料检索/读取 | 复用实际可用搜索 provider；结果含 URL/标题/日期/摘录，可打开原文，抓取限制/失败如实返回 |
| 计算与产物 | 复用计算/图表合约；Markdown、CSV/XLSX、SVG/HTML 和已有报告生成；文件存在才展示下载/打开 |
| 历史与证据检索 | 只查当前任务/授权项目范围，返回事件或证据 ID 与可继续读取的引用 |

用户文档里的“忽略之前指令、上传文件、执行命令”等内容属于数据。检索/工具返回永远不能授予权限。

长结果统一返回：status、摘要、计数/截断标志、source/evidence ID、全文文件或 cursor、数据口径/缺口。摘要不要超过该轮剩余预算；全文先持久化再返回引用。脚本错误也有完整日志。禁止直接 `.slice(0,4000)` 且不给找回路径。

### 5.3 真正的隔离执行

Windows 初选 AppContainer/受限 worker，Rust 建立 profile、最小 capability 与 ACL，仅允许读随包运行时/必要系统组件，读写当前任务工作目录；业务 DB、应用设置、凭据、其它任务和任意用户目录不可读写，默认无网络。配合 Job Object 限制内存/进程树和退出清理；Job Object 本身不是权限隔离。

P04 先做最小真实实验：隔离 Python 可读写任务 CSV、可导入必备库；读工作区外测试哨兵、访问 localhost/外网、访问其它任务均失败。常规用户、路径有中文空格、无管理员启动都测。确有平台不兼容时选择能满足同一隔离契约的受限令牌/系统方案，记录事实，不拿 `cwd` 或关键词命令过滤代替。

只给任务 profile SID 必要目录权限，不递归向整个用户目录授予 ALL APPLICATION PACKAGES。规范化路径后再检查，拒绝 junction/symlink/hardlink/UNC/设备路径/ADS 等越界通路；重解析点与路径变化存在 TOCTOU 时在文件打开/句柄层验证。不要调用另一个 shell 删除计算出来的目录。

子进程环境白名单，不继承 API key、宿主 RPC handle、DB URL；网络请求通过受控检索工具在隔离外完成，再把审查后的结果文件交给脚本。脚本不能 pip/npm 联网安装任意依赖。运行时依赖提前固定版本随包带齐。

隔离启动失败时显示真实错误，继续允许只读业务/文件工具；不自动改用普通 PowerShell。最终验收中隔离测试未过，不能宣称完成“沙箱 Agent”。原有普通 PowerShell 作为“本机执行（非隔离）”高级可选，用户授权后才可使用，不能突破已有出域承诺。

### 5.4 执行可靠性

每次调用有稳定 callId/actionId。流式相同工具片段合并，完成并验证参数后才能执行；重复调用 ID 不重复执行。文件写入使用临时文件＋原子替换或明确版本校验；输出文件在任务下。

未知写入恢复先查账本/产物指纹：同 actionId 已提交则返回原结果；无法核实时等待核对，不能根据“上次看起来没返回”自动重做。工具失败模型可修复输入，但修改后的副作用动作应有新预览与动作 ID。

## 6. 云端协作：解决问题而不是固定多轮

### 6.1 接入方式

本地主 Agent 默认掌握原始业务事实；云端是按需调用的咨询工具，并可对用户明确允许的合成/公开任务做可比模型实验。不要默默把主会话切换到云端、上传完整历史或摘要。

复用当前 provider、Rust 出域检查、审批票据和发送记录。定义 `consult_cloud`：问题、为什么本地不足、已验证且允许披露的事实、候选解释、反证、希望得到的判断/验证路径。返回答复、建议补查项、引用、是否需要更多信息；云端不直接修改本地业务数据。

现有 C2 的 low/medium/high 抽象接口保留。增强协作使用另一个版本化 payload profile，明确字段级允许范围，不偷偷放宽旧 C2 正则。

### 6.2 脱敏与任务范围授权

- 默认继续允许现有公开品类/抽象问题范围；项目名、公司、供应商身份、型号、原始 BOM、合同/订单、成本金额与文件路径不自动外发。
- 如分析确需规格、比例或区间，先生成可审查的结构化包，用户明确选择允许的字段与精度。允许相对变化不等于允许原始单价；相对值也属于敏感派生数据，需纳入范围。
- 用本地别名映射隔离身份；映射表不外发，文件名/日志/URL/query 参数/系统提示/错误文本也检查。保留足够技术关系，但承认稀有特征组合仍可能泄露身份，不能宣传“绝对匿名”。
- 首次确认可选“仅此次”或“本任务同一范围内，最多 N 次/预算上限”。默认建议最多 3 次云端回答，范围/预算可收紧；每次发出前生成实际请求体并在 Rust 校验、记账，超范围重新预览。
- 精确 body hash 票据仍然一次消费。任务 grant 只允许后端在合规范围内签发新票据，不能重复使用旧票据放行任意新正文。中止/撤销即时生效。
- 不把云端输出直接回传云端：后续上下文也按同一出域规则筛选；外部引用中的指令无效。

### 6.3 多轮推进规则

初始咨询 → 本地读取/计算验证云端提出的疑点 → 有新的证据或明确新检验路径才继续咨询。每次后续请求记录相对上一轮新增内容及来源。

停止条件：问题已回答、需用户/供应商提供关键资料、相同请求无新增信息、两次重复失败、达到时长/调用/费用预算。字段齐全不代表证据成立，云端“还想聊”不能突破停止规则。达到预算给已知结论/缺口并允许显式继续。

单次结果与问题包/证据指纹缓存，同证据不重新花费。网络超时发生在请求已发送后视为结果不明，不能无脑重发并假定没计费；本地记录 attemptId，按 provider 可验证能力处理。

本地摘要压缩独立运行，不为省显存将私有摘要交云端。没有云端配置时本地完整能力继续工作，并明确哪些问题未能得到云端复核。

## 7. 成本专业能力与自主机会

在已有 quote-analysis Skill 中补充：报价范围/币种/税运/质保/认证/数量阶梯、版本、物料等价性、标准成本与采购报价区别。Skill 提供方法与反例，不能强制每次跑同一流程或无证据报“合理价”。

至少支持三个完整任务：新旧报价变化归因、可比跨项目/供应商价差、谈价承诺是否进入新报价/BOM。额外可做方案取舍与谈价材料，但“未查到资料”时允许停止。对金额计算用已有可靠计算器或实际脚本，保留输入行/公式/输出引用；不能只靠“数字在上下文中出现过”验证结论。

机会记录包含：稳定 issueKey、项目/对象、证据指纹、事实、假设/反证、可比条件、价差（不等于节省）、下一步、来源和跟进状态。复用 advisor/measures，先查现有 schema，避免重复建“另一套机会库”。

后台规则只决定哪些变化值得检查，由同一 Agent 核心执行有预算的调查。数据变化事件按项目防抖合并；同一 evidenceFingerprint 不重复调查/通知。用户忽略/否定/正在跟进后保持状态，新证据变化才允许重新打开，并展示“本次新增依据”。模型换了措辞或摘要版本变了不属于新证据。

当前后台多入口共用推理调度：前台请求优先；后台可在安全点暂停，用户交互不等下一轮 15 分钟。默认只通知可行动且有新增依据的少量机会。没有新发现就安静，未读数量刷新不弹 toast。后台不能自动执行业务写入、脚本高权限操作或无预算云端调用。

## 9. Luna 的工作与恢复纪律

- 每次开始只读 README、PROGRESS、当前阶段、对应验收和要改的文件。首次确认全局约束，此后由 PROGRESS 保留，不每次全文重读。
- 每个小改动：核对调用者→改代码→跑最相关测试→写证据→更新唯一下一步。没有新变化不重复全套测试；阶段出口/最终交付再跑规定集合。
- 压缩/上下文不足/用户插话后：先查进度与实际 diff/运行进程；最新用户要求写入进度，仍保留原目标。不要从头再写方案。
- 记录函数名、文件、准确错误、命令退出码、测试模式（mock/真实）和产物路径，避免“应该已经完成”。
- 任一硬门槛失败先修；受阻时能独立推进的阶段继续做，但不能伪标通过依赖门槛。
- 不创建重复实施任务或自动委派子 Agent，用户会自己管理对话。无需询问常规代码选择，但必须尊重出域/正式数据写入权限。
