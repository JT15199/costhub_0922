## P1：原始事件完整保留只在测试中实现，生产未接入

位置：`src/__tests__/piHost.integration.test.ts:56-58` 对比 `src/ai/piRuntime.ts:327`、`src/components/AiPanel.tsx:689-698,754-755`、`src/aiPanelChat.ts:46-49`。

测试自己订阅 message_end，将完整消息推入 rawEvents，所以“保留原始事件”断言能通过。生产没有对应持久化订阅：工具结果进入 UI/内存数组，检查点事件只保存 messageCount/pending/workspace；savePiState 是覆盖同一个 pi_state_json。聊天表主要保存用户输入和最终答复，不是所有工具交互原文。

现在压缩真正删减工作上下文后，早期只存在于 Pi state 的工具结果和中间消息会被覆盖；历史检索也无法从计数事件找回它们。业务写动作账本不能代替全部只读工具证据。

返修：先将完整原始消息、工具调用及结果追加持久化并分配稳定引用，再提交压缩工作状态。追加失败不得继续提交会丢失原文的压缩。测试必须调用生产持久化路径：构造只有早期只读工具结果含有的唯一证据，压缩三次、关闭恢复后，仍能通过生产 search_history/read_history 找回原文。不要在测试里另建 rawEvents 数组替代实现。

## P1：新任务宿主未接入实际界面接管

位置：`src/ai/piHarness.ts:10-46`、`src/ai/piRuntime.ts:285`、`src/components/AiPanel.tsx:423,741-756`。

Map 现在能保留宿主，类支持 get/subscribe，但生产界面没有调用 PiTaskHost.get 或 host.subscribe。每次运行创建随机 runId，界面仍依赖旧组件的 refs、回调和闭包。新增测试手动退订/重新订阅，证明的是类接口，不能证明组件重建后会查到任务、恢复输出、接管停止和 steer。

返修：将会话与当前 taskId 关联，界面挂载时查询并订阅运行中的任务，所有停止/steer/排队使用该任务；将持久化与执行所需操作从旧组件闭包移出。至少做一次真实组件卸载再挂载的集成检查，确认没有第二次任务启动且仍能看到进度和停止。当前仍是 renderer 内宿主，不是原计划的独立 Node/Worker；如采用替代架构，应明确边界并补齐同等保证的测试。
