# 本地模型 Excel 批量处理优化 · 2026-09-16

## 已完成

- Pi 常驻 `analyze_spreadsheet`，无需终端权限。支持 xlsx/xls/csv 的结构预览、按明确列映射批量计算数量×单价、模块汇总、小计核对，以及两表精确标识对比。
- inspect 返回工作表范围、有限合并单元格信息、最多 6 行×12 列样例；模型只需识别列和明细范围。复杂分段应先核实范围，不能把合计行混入明细。
- calculate 的完整明细逐行保存到任务目录 `.costhub-results`，模型只接收汇总、前 20 个模块和少量异常/差异。原生 read 可按行续读，保留证据，不需要把所有结果读回模型。
- 文件内容 SHA-256 校验与最多两份工作簿缓存；相同计算复用已有结果。连续三次请求相同计算且文件未变化时，本轮工具入口关闭，模型根据已有证据回答，不宣称未完成工作已经完成。
- 预读附件从最多 200 行降为 8 行；普通 Excel 读取默认 8 行，显式分页仍保留。
- 修复 Pi 已完成原生数据读取/分析后仍可能触发业务工具补跑的判断。
- 内置报价 Skill 和系统提示同步工具分工；不引入新依赖、不新增云端请求、不放宽文件权限或业务写入审批。

## 计算边界

- 单价/数量缺失、模糊格式或公式值不当零；显式数值零可计算。
- SheetJS 不执行公式，也不信任公式缓存。若数量与单价是明确数值，可重新计算金额并对比；来源公式小计仍标待核实。公式出现在单价/数量时，该行金额保持未知。
- 匹配按指定标识列精确进行，重复或不完整标识不自动配对；数量/计价口径不同不直接计算可比差额。参考独有行不计为节省。
- 模型仍负责映射与业务口径判断，工具不会自动证明规格、税率或供应商条件可比。不做隐式税汇率换算，不把差额称为实际收益。
- 当前优化重点是 Pi 附件报价链；没有为所有历史工具加通用缓存或循环拦截。大段文本语义分析、复杂表头和公式依赖仍可能需要进一步读取或核实。

## 验证

- 新增 7 项专项测试通过：1 万行整表汇总、零与缺失、公式缓存、重复标识、小计冲突、两表口径及参考独有项、内容变更失效、路径拒绝和取消；真实 Pi 循环（模拟模型传输）验证工具常驻、无终端计算、不多跑读取和重复收尾。
- 合成 1 万行样例：全部行由工具处理，汇总 65,000；模型计算结果摘要小于 2,500 字符，完整证据文件包含 10,001 行。字符数是该样例的上下文负担指标，不是 token 实测或 27B 耗时承诺。
- 全量测试首次 385 项通过、1 项加载超时、2 项跳过；超时的 costPackage 测试单独重跑通过。后续新增两项 Pi 集成测试和最终 7 项专项检查通过。
- 未读取公司数据，未调用公司 27B 模型。实际速度需在同一模型、上下文、报价文件和任务下比较首轮输入、工具次数、总耗时。
