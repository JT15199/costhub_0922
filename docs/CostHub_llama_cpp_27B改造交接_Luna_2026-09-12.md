## 3. 先处理的初稿风险

以下是接手时应优先检查的具体位置，不是要求另起一套实现：

1. **端点与请求体一致性。** `startOllamaStream` 根据 `endpoint` 选 `/api/chat` 或 `/v1/chat/completions`，新的 `buildLocalChatBody` 目前只按 backend 区分。Ollama 默认/兼容端点可能收到原生请求体。必须查所有调用者，保证路径、字段、响应解析成套一致；不能只修 llama.cpp 主聊天。
2. **流监听注册期间取消。** 目前多个 listener 顺序注册，部分 unlistener 最后才入数组；注册过程中取消/异常可能残留监听，`onError` 也可能重复。需要保证每个请求只终结一次，取消后不启动新请求、不再更新 UI。
3. **工具参数恢复。** `piStream` 现在保留解析失败的字符串，交给 Pi schema 校验。验证真实依赖会把失败反馈给模型且不执行工具；不得改成 `{}` 后继续执行，也不能把一项损坏当成整轮所有动作都可重试。
4. **工具错误标志。** 当前 Pi 依赖并非仅靠工具返回对象中的 `isError` 判断；新增 `afterToolCall` 已做传播。验证最终模型消息、UI、检查点均一致。
5. **分页细节。** 部分工具只把分页信息放在 warning 字符串，BOM 才有明确 pagination；项目分页超出末页会被描述成“没有项目”；快照 `limit` 从每项目条数变成全局分页，需检查调用者和旧描述。统一可读取契约并补边界测试。
6. **上下文一致性。** `estimateContextTokens` 已支持 thinking，但 `safeTail` 等仍按不含 thinking 的文本估算；图片用构造很长占位字符串估算，应该改为明确的保守 token 开销，不把 base64 当普通文本，也不能声称估算是精确分词。
7. **模型配置缺 UI。** `loadModelOptions` 已有后端，但界面不能编辑。Qwen3.8 识别目前依赖模型名称；GGUF 路径、别名、hash 可能无法识别，所以必须允许用户显式选择/覆盖，不能静默断言已应用 Qwen3.8 策略。
8. **进展卡仍是初稿。** `AiPanel` 每轮 append 同一个 `model-round` ID，可能重复或一直显示运行；不再清空正文也可能使中间回复连续拼接、最后又整体替换。要保证进展与最终答案各自稳定，失败/取消能终结状态。
9. **探针元数据与导出。** `modelFingerprint` 的 key 包含模板和本地路径，当前会合并到探针结果。诊断导出必须显式选白名单字段，不能直接导出整个对象。
10. **旧注释和提示词。** 仍有“thinking 仅用于显示”“4B 固定 8K”“工具结果最多 4000 字”“不管理 llama-server”等过时说明。功能定稿后一起同步，不能只换文案不接行为。
