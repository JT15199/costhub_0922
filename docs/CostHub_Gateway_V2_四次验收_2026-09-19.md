# Gateway V2 四次验收

结论：上轮保密文本误判已通过回归，基础安全边界明显改善；完整规范仍未全部验收通过，主要剩网络取消与历史溯源。不把尚未实测的界面、云端或公司电脑模型体验算作通过。

## 已通过的修复

- 默认分类器不再仅凭 public 来源标签放行，未核实内容为 UNKNOWN。
- CloudSafe 发送前审阅正文；使用 verified 元数据，审批与实际请求体哈希绑定。此前“保密新品”合成文本现在被拒绝，有对应测试。
- 失败/取消加入 unknown 发送状态，不再一律认定没有外发；attempted 后异常补终态。
- 历史运行选择入口已添加，metadata_unknown 显示未执行；规则分类器标识已说明。
- 既有项目隔离、关键事实保留回归通过。

## 仍需返修

### P1：取消并没有取消 Rust 网络请求

`src/trendService.ts:335` 的 invokeAbortable 仅拒绝前端 Promise，注释明确允许 Rust 请求继续完成。传递 signal 只到这个包装，不是传输取消。`provider_cloud_http_request` 的调用参数也未带可取消请求标识。

这次已诚实标为发送未知，较上轮改善，但用户按停止仍可能继续发送/等待服务端。至少要在取消前检查、取消期间通过 requestId 通知 Rust 并终止网络 future；已发送的数据不可撤回。若保留当前限制，界面必须明确“停止等待，后台请求可能继续”，不能宣称网络已取消。还应将后台最终结果留在审计中，而不是丢弃。

### P2：历史事件与信息归属不属于同一时间点

`src/components/AiPanel.tsx:1318` 给 GatewayTracePanel 始终传 workingStateRef.current；切换历史运行仅切换 events。用户选择旧轮次时仍看到当前事实/项目状态，旧轮已覆盖或删除的事实不能复原。底部提示说明了限制，但没有满足历史逐项溯源要求。

建议复用每轮检查点保存该轮投影/状态引用，显示同一轮实际纳入、排除的条目与依据。来源目前是 ID 文本，尚不能点击定位消息/文件；“实际外发”也未逐项关联具体 requestId。

### P2：长会话历史被固定窗口截断

AiPanel 调用 loadPiEvents 默认只取最近 500 个事件，包含非 Gateway 事件，没有翻页入口或“历史不完整”提示。100 轮工具会话容易超过这个窗口。按 runId 查询/分页，不应仅扩大固定数字。加载失败还 catch 为 []，会被解释成没有事件。
