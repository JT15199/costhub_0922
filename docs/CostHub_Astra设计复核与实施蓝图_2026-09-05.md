## 1. 执行摘要

### 1.1 三个最重要的判断

1. **CostHub 已有成本工作台的主体，下一步应修通事实和决策链，不应扩充页面。** 五个一级入口、项目工作区、品类规格、BOM 版本、招标、原声、成本长城、成果库和受控云端都已存在。真正影响使用的是：一个结论读取了不同时间的 BOM、规格、费率和报价；同一数据还有旁路维护；正式与草稿的状态边界不够可靠。
2. **最优先的业务问题是“数字总额正确但承诺错误”与“历史事实会漂移”。** 跨领域依赖包被拆成比例挑战，可能生成物理上不可实现的领域目标；冻结成本包可能把领域实际显示为 0；旧快照明细使用今天的行和价格。已有全绿测试不能证明这些口径成立，本轮用虚构数据复现了新的边界。
3. **AI 的下一步是最小可审计执行闭环，而不是更多 Agent。** 现有白名单工具、Pi 接入、传统协议适配、原声分块和巡视规则值得复用；需要统一运行身份、取消、恢复、输入版本、证据及结果保存。云端已有真实后端校验和 C2 防重放，但请求头、凭据、授权存储和完整请求构造仍需收口。

成熟度判断：**可支撑个人成本录入和辅助分析的工作版本；尚不能把所有冻结、目标承诺和阶段报告直接当成审计级事实。** 这是基于下面列明的代码与离线样例的产品判断，不代表已验收正式业务数据、登录后所有页面或真实模型表现。

最终形态是一个本地成本工作台：

> 今日待处理 → 进入项目 → 看阶段缺口 → 在唯一事实页处理 → 人工确认版本/决策 → 自动形成阶段交付 → 量产后持续发现机会 → 复盘复用。

项目由“稳定对象入口”组织，阶段决定首屏任务和交付要求。阶段页不再复制一套 BOM、报价、报告或 AI 编辑器。

### 1.2 保留、收敛与边界

| 处理 | 内容 | 用户价值 / 数据要求 / 复杂度 / 不做后果 |
|---|---|---|
| 保留 | 五个一级入口、资料库、项目内五个工作区、全局同一个 AI 面板 | 延续已有使用路径；沿用当前数据；低；重做会增加学习与回归成本 |
| 保留并补齐 | 规格模板、BOM 版本、变更包、目标版本、招标矩阵、单竞品成本长城、共享原声分析 | 已覆盖核心 ODM 工作；补关系与证据即可；中；另建同类功能会扩大事实分叉 |
| 合并 | 项目“ODM 报价”与招标报价；阶段快照与 BOM 版本的事实引用；AI 建议与巡视事项状态；原声的多入口 | 同一数字只改一次；需要旧记录来源标签；中；继续并存会出现两套报价、两次处理 |
| 删除或降级 | 硬编码进度、无目标的“达标”、旧快照伪历史明细、不可达旧页面分支、登录页显示真实密码 | 防止误导与泄露；不新增数据；低至中；会继续损害信任 |
| 暂缓 | 多 Agent、团队权限、云同步、库存/良率/物流/税务、通用工作流、复杂置信度评分、泛化 Excel 猜表 | 与个人 ODM 职责及规模不匹配；当前无必要数据；不做；不会阻断核心成本闭环 |

最大风险分三类：业务上是错误领域目标与漂移版本；体验上是长页面、多次维护和“停止但后台仍在计算”；安全上是登录密码明文副本、渲染进程可接触凭据/授权，以及网关未约束完整请求。

## 3. 用户任务与主流程

### 3.1 组织规则

[建议] 阶段是项目状态与交付索引，对象页是操作位置。项目总览首屏固定四块：当前阶段、事实版本、阻碍下一阶段的缺口、下一步动作。阶段不是完成率；未知阶段保持“待确认”，不从项目排序推断。

统一的轻量状态语义：未开始 / 进行中 / 待确认 / 已确认 / 有缺口。正式冻结事实不可原地改写，后续修改形成新版本。进入下一阶段可以带着已明确的风险，不为“流程完整”建立审批引擎；但不得把缺价 BOM 或未对账报告标为正式成本事实。

| 阶段与入口 | 输入 / 关键判断 | 输出与状态 | 缺口和下一步 | AI / 人工边界 |
|---|---|---|---|---|
| Charter：项目总览“建立估算” | 定位、财务目标、关键规格、上代版本；销量可选；研发方案与风险可为短说明 | Charter 估算场景、引用版本、假设列表；估算/待确认 | 无上代允许历史参考；无研发价格显示未定价，不给伪区间；下一步确认规格与参考版本 | AI 列历史可比项目和缺项；人选参考、确定财务输入和风险 |
| 成本策划：项目→成本策划 | 当前/上代可比基线、规格变化、完整包、费率、领域映射 | 调整后基线、可行领域目标候选、未覆盖缺口；草稿/待确认/目标版本 | 依据不足回到包或报价；下一步确认可行方案与目标版本 | 规则算金额，AI 解释差异；人确认可比条件、方案与目标 |
| 价值取舍：策划内切换视图 | 评论主题、人工 Kano、规格、模块成本、证据 | 保持/加强/收敛/删除/待验证决定，关联规格变更草稿 | 无评论允许人工主题；无成本只给价值判断，不能给 ROI；下一步验证或进入报价规格版本 | AI 归纳/找证据/提问；人决定 Kano、模块、方案和验收 |
| 多轮报价：项目→报价与招标 | 已选择规格版本、明确轮次、供应商、Excel、总额/单价口径 | 每批原始报价、匹配结果、可比覆盖、纯价格/数量/新增删除差异、议价清单 | 缺匹配保留未匹配，不作低价；下一步要求补报或创建下一轮 | AI 建议匹配和议价措辞；人确认可比关系与对外材料 |
| CDCP 定点：招标→定点 | 2–3 家实际有效报价、目标、供应商选择、原因、未兑现措施 | 定点记录关联报价批次与规格；CDCP 成本包；已确认/有保留事项 | Open BOM 未到则标“定点报价事实，BOM 待到”，不冻结空 BOM；下一步导入中标 BOM | AI 汇总设计、商务、竞争证据；人确认定点及阶段交付 |
| 试制 PDCP/ADCP：BOM 与版本 | award_openbom、试制变化、验证结论、改价记录 | 工作 BOM、变更包、阶段评审及下一版本；执行中/待验证 | 每个变化保留前后和来源；下一步关闭临时估价、验证方案 | AI 对账变更与列未解释残差；人确认依赖、价格和生效 |
| 量产冻结：BOM→冻结量产版本 | 最终 BOM、量产前谈价、规格、费率、SKU 差异、未关闭风险 | final_bom 完整事实快照和目标达成；冻结/有明确保留事项 | 缺关键价格或对账错误阻止正式冻结；风险说明可随包交付；下一步巡视 | 规则冻结与守恒检查；人批准量产事实、保留事项 |
| 量产后降本：项目→措施/待处理 | final_bom、后续价格版本、行情证据、上次谈价时间、措施 | 信号→候选→措施→实现/未实现/放弃；预测与实现分列 | 行情不等于可买价；落实需新报价/BOM 证据；下一步谈价/验证/关闭 | AI/规则发现线索；人批准措施，确认新价生效和实现额 |
| 复盘：总览→生成复盘包 | Charter/CDCP/final_bom、目标版本、变更贡献、谈价与措施记录 | 目标达成、设计/商务/规格贡献、竞争引导、失败判断与复用经验 | 未解释差额单列；无证据不补故事；下一项目通过引用复用 | AI 写有来源的叙述草稿；人确认因果归属、经验适用条件 |

预计销量只用于明确“按预计销量测算的潜在金额”。没有实际销量记录就不声称年度实际收益，也不为此引入库存或 ERP。

### 3.2 CDCP 之后的交付不再手工维护第二份 PPT

项目定位、版本化规格差异、成本桥、实际/目标、定点、设计/商务/竞争、后续措施和缺口由同一阶段包生成。用户可编辑的是“判断说明/贡献原因”，金额和版本从冻结快照来。需要纠错时回源编辑并生成新包，不在 PPT 页面再维护一份数字。

价值：减少重复 PPT 劳动；数据：现有版本和短判断说明；复杂度：中；不做：资料库看似丰富但正式交付仍需手工对账。

## 5. 核心页面体验设计

### 5.1 所有页面共用的状态与窄窗契约

[建议] 沿用 Ant Design 和现有 CSS 变量，不再建新组件库。以下契约对 5.2–5.11 每页生效：

- 金额旁标口径、单位、版本；未定价显示“待补价”，已确认零价显示“0.00（已确认）”。无目标、无证据与错误是不同状态。
- 第一次加载显示有标题的骨架；刷新保留旧内容但标“正在刷新，暂不可确认”，不能把旧内容伪装当前。请求错误显示“读取失败”和就地重试，不用 catch→空列表宣布没有数据。
- 页面切换携带 projectId / skuId / versionId / section / objectId。复用现有导航事件；先确定项目再打开子视图和行。没有对象时说明“已删除或不可用”并回项目，不能落到另一项目同名对象。
- 只有当前 runId / projectId / 输入指纹匹配的响应可以更新页面；未保存草稿离开提示“保留草稿/放弃”，已开始任务固定归属原项目。
- 1100×700 物理窗口下，必须分别检查 100%、125%、150%。150% 意味可用 CSS 空间进一步缩小：导航收起，AI 使用覆盖抽屉；主区单列，页头按钮换行，表格局部横向滚动，弹窗内容内部滚动且确认/取消可见。禁止只压字号或强制全局横向滚动。
- 次操作放更多菜单；正文和表头正常阅读字号，不能依赖 10px 文字。长名称两行+完整悬浮提示；型号可省略但可复制。键盘可达，有明确焦点；颜色之外用符号和文字区分。
- 成功提示写明“保存草稿”“确认目标 v3”“生成冻结包”，不只说“成功”。需要人确认的是正式写入/外发；普通读、筛选、展开证据不反复弹确认。

## 6. 成本领域方法

### 6.1 口径先行

[建议] 金额默认人民币元/台。保留供应商原报精度；计算不逐行过早取两位小数，展示两位；正式汇总采用统一固定精度（例如微元整数，检查安全整数范围），最终按约定舍入，舍入差单列。不要到处用浮点容差掩盖业务残差。

~~~text
行金额 Li = 单位价格 pi × 整机用量 qi
可分解成本 D = 物料 M + 包装 K + ODM 加工费 A
平台费 F = D × 平台费率 r
标准成本 S = D + F = D × (1+r)
财务可分解目标 TD = 财务标准成本目标 TS ÷ (1+r)
利润/管销研参数不进入 S
~~~

当前先复用百分比平台费，基数固定为 D；不新增无人使用的费率引擎。若真实合同以后有固定额平台费，再增加明确模式，不能两种同时生效。

成本层和业务领域是两个维度：cost_layer 区分 material/packaging/odm_processing；domain 区分大硬件/大结构/多媒体/互连/包装等。main_category 是物料分类，不能直接等同业务领域。ODM 加工费可作为“公共费用”一行独立承担目标，平台费只在整机汇总计算，避免分入领域后再加一次。用户可在品类内确认不同领域清单，先用既有 categories/映射承载，不建组织管理系统。

### 6.2 基线、机会与目标的定义

| 概念 | 本文口径 | 最少输入与禁止行为 |
|---|---|---|
| 当前实际 C | 当前选定 BOM/报价事实范围内的成本，不从目标倒推 | project/SKU/来源版本、数量、有效价格；草稿实际必须显式标草稿 |
| 历史基线 H | 被人工选定的历史可比版本及其成本 | 历史项目与固定版本；不能自动取整个库最低行拼成一台机器 |
| 可比器件最低价 | 在已确认同功能/规格/用量口径、适用时间及有效报价条件的集合内取最低单位价 | 只要求来源、比较条件和适用日期；样本1条标“单一参考”，不是充分竞争价格 |
| 调整后基线 B | H + 已确认必要规格/方案变化 + 已明确纳入的已实现价格变化 | 每条调整有来源和生效范围；没有报价的新增依赖保持未知 |
| 未来机会 O | 未计入 B，方案可行、依赖完整、未与别的机会重复的包净节省 | 包、来源版本、可行依据、是否已实现；空 evidence 不能用 confirmed 状态兜底 |
| 风险 R | 已知但未落实的额外成本情景或准备额 | 一句原因、影响金额或上下界、处理动作；不要求伪概率，不再设三级可信度 |
| 领域可行目标 T | B 加上人工选定完整包的有符号成本变化 | 领域金额可以增加；不是财务缺口按机会比例切分 |
| 未覆盖缺口 G | max(0, 可行标准成本 − 财务目标) | 必须保留，不能靠按比例压数消失 |
| 已实现节省 | 同一可比范围的前后事实版本之差，并有生效证据 | 新报价/BOM、日期、数量口径；实现后从未来机会移除 |
| 达成情况 | 当前实际 − 领域目标；≤0 达成，>0 超标 | 目标不存在为未设目标；价格缺失为无法判断；不使用默认0 |
| 贡献归属 | 对已发生变化的规格/设计/商务/其他原因归类 | 一条金额变化只有一个主归属；竞争是原因标签，不再重复加一笔收益 |

[事实] 当前buildTargetDomainRows在architecture.ts:124–141还会按part键取最小值，并允许project_id=0且category相同的module/project决定压低整个领域；preview读取没有携带完整可比条件。[推断] 某电源模块80元的通用基线可能被错误用于整个大硬件领域。必须先明确基线适用于哪组行/规格/版本，再在该范围计算；不能仅因分类相同就跨模块或跨领域取最小值。

最低价只能说明“此条件下有人报过/确认过这个价”，不是今天可买、可量产、可替代的证明。物料级价差、模块替代和整机报价降幅若指向同一节省，必须去重或选其一。

### 6.3 目标形成：选完整方案，不按比例凑数

对包 k，记录各领域的有符号变化 Δkd：

~~~text
Δkd = 包在领域d的实施后成本 − 实施前成本
包净节省 Ok = −Σd Δkd
领域目标 Td = Bd + Σ(已选包k) Δkd
可行可分解成本 = Σd Td + 公共加工费目标（若未放入领域表）
可行标准成本 = 可行可分解成本 × (1+r)
财务缺口 = max(0, 可行标准成本 − TS)
带风险成本 = (可行可分解成本 + 已确认风险准备) × (1+r)
~~~

选包变量默认只有“采用/不采用”。只有本身可独立切分、每一子包都能交付并被人确认时才拆小包；不能把屏幕方案实施 25%。报价尚未接受的“挑战价格”是谈判意向，不能算已确认可行机会。

跨领域包保留完整向量，一位措施责任人协调依赖；各领域看到自己的增减额。互斥方案选一个；共享前置料/同一议价证据不能重复省。已经体现在 B 的包显示“已计入”并禁止二次扣减；无来源的旧包默认为待复核，而非未来机会。

旧总方案第9.4节的机会比例分配需要推翻：它能对总额做封顶，却不保证完整方案可实施。R01 就是反例。本文不引入优化求解器；当前项目规模下人工选 2–5 个包、规则检查依赖/互斥/守恒更可靠。

### 6.4 屏幕替代与外围 IC 的完整示例

以下全为虚构单台成本。历史可比成本 H=600，已确认规格升级 +40、已实现商务降价 −10，调整后基线 B=630。−10 已体现在当前事实中，不能再放未来机会。

基线构成：大硬件390、大结构120、多媒体40、互连40、包装20、ODM加工20，共630。平台费5%，当前标准成本661.50；财务标准目标630，对应可分解目标600，尚需30元依据。

完整屏幕方案 P：

| 依赖行 | 领域 | 实施前数量×单价 | 实施后数量×单价 | 有符号变化 |
|---|---|---:|---:|---:|
| 屏幕替换 | 大硬件 | 1×300 | 1×260 | −40 |
| 原驱动 IC 移除 | 大硬件 | 1×20 | 0×20 | −20 |
| 新驱动 IC 必增 | 大硬件 | 0×35 | 1×35 | +35 |
| 外围必增3颗 | 互连 | 0×2 | 3×2 | +6 |
| 原连接件移除 | 互连 | 1×5 | 0×5 | −5 |
| 新连接件必增 | 互连 | 0×9 | 1×9 | +9 |
| **包合计** | | **325** | **310** | **−15** |

大硬件净变化 −25，互连净变化 +10，整包只省15。仅展示屏幕 −40 会夸大25；只算删除/节省行会夸大更多。报价或工程确认中少一条必增 IC，整包状态是依赖未完整，不能承诺15。

另有独立、已确认的 ODM 加工费包 Q：20→15，省5，未计入基线。选择 P+Q 后：

| 领域/公共项 | 调整后基线 | 已选包变化 | 可行目标 |
|---|---:|---:|---:|
| 大硬件 | 390 | −25 | 365 |
| 大结构 | 120 | 0 | 120 |
| 多媒体 | 40 | 0 | 40 |
| 互连 | 40 | +10 | 50 |
| 包装 | 20 | 0 | 20 |
| ODM加工 | 20 | −5 | 15 |
| 可分解成本 | 630 | −20 | 610 |
| 平台费5% | 31.50 | −1.00 | 30.50 |
| 标准成本 | 661.50 | −21.00 | 640.50 |

财务标准目标630仍缺10.50，必须保留“还缺10元可分解依据”。不能再从大结构随机减10凑齐。若有新 IC 验证风险准备5，风险情景为615×1.05=645.75，距财务目标15.75。风险准备单列，不自动写进实际 BOM；用户可以明确将该情景选为目标承诺的保护边界，系统同时展示不含风险和含风险两条口径。

### 6.5 达成率、变化拆分与复盘

领域主指标使用差额：C−T，正为超标。需要百分比时区分：

- **相对目标偏差率**：(C−T)/T；T>0且数据齐全才计算。
- **降本挑战进度**：(B−C)/(B−T)；仅 B>T 时有意义，可限制显示0–100%并另标超额。若 T≥B（例如互连因必要依赖增成本），显示实际/目标和差额，不计算降本进度。
- 未定价/未设目标/历史不完整均为不可计算；C=0只有经确认的真实零成本才参与。

成本桥保留完整勾稽：

~~~text
ΔD = 规格贡献 + 设计贡献 + 商务贡献 + 其他已解释 + 未解释残差
ΔS = (D1−D0)×(1+r0) + D1×(r1−r0)
~~~

平台费率变化单列；包可以跨领域但整笔贡献只计一次。上例历史600→最终610：规格+40、已实现商务−10、设计包−15、加工商务−5，净+10；同5%费率，标准630→640.50，净+10.50。竞争引导可以标签关联商务−5及谈判过程，不能再记竞争降本−5后算出假总额。

同一物料价格/数量同时变更，固定分解次序：

~~~text
价格变化 = (p1−p0)×q0
数量变化 = (q1−q0)×p1
两者之和 = p1q1−p0q0
~~~

新增/删除各自按新/旧行完整金额；替代包优先按包归因，防又逐行累加一次。重复器件可以按稳定匹配关系聚合金额，但必须保留所有源行。图只展示前12项时，余项合成“其他变化”且仍含舍入残差，不直接丢弃小额。

量产后措施区分预测节省、已确认生效单台节省、按预计销量测算的潜在收益。上次谈价日期引用项目/物料可比报价或确认事件，不能使用物料库 updated_at 替代。复盘记录错误判断也要链接当时版本，避免用今天信息解释过去决定。

### 6.6 价值取舍的轻量方法

采用“Kano 辅助分类 + 功能/成本核查”的实务方法，不声称电商评论构成完整 Kano 问卷或统计研究。

~~~text
原评论ID → 候选主题 → 人工Kano/暂不确定
→ 关联产品规格 → 支撑模块/BOM版本 → 当前成本
→ 保持/加强/收敛/删除/待验证 → 验证结果 → 确认变更包
~~~

每个主题只要求短理由，不要求用户填满意度曲线、支付意愿或权重矩阵。评论去重数可用于定位值得查看的问题，不能直接换算价值分、愿付价格或成本目标。AI 返回原评论 ID 集合；统计由代码去重，不统计“有几个分块提到了主题”。

人工确认是稳定记录：AI 重跑只更新候选证据，不覆盖决定；改名保留同一主题 ID，主题合并需用户选择，缺席主题标“本轮未出现”而非删除。全局/其他项目主题作为参考，采用时明确复制判断依据至当前项目，不能用 project_id=0 静默共享可编辑决定。

| 方案 | 用户价值 | 数据要求 | 复杂度 | 不做后果 |
|---|---|---|---|---|
| 统一金额与未知值 | 数字能对账 | 行口径、来源、已确认零价 | 中 | 缺失继续伪装0 |
| 业务领域映射 | 目标交给正确领域 | 每模块/行一个领域，可批量确认 | 中 | 分类表代替责任领域 |
| 完整包选取 | 可执行的目标承诺 | 前后行、依赖、来源、已计入标记 | 中 | 比例目标无法落实 |
| 版本化基线与复盘 | 知道当时承诺和实际贡献 | 版本链接、简短原因 | 中 | 反复重算改写历史 |
| 轻量价值链 | 评论帮助规格取舍 | 稳定主题、规格/模块链接、验证结论 | 中 | 主题统计无法影响决策 |


## 7. AI Agent 架构：复用现有能力的最小 Harness

### 7.1 一条任务生命周期，两种模型协议适配

[建议] 不再引入 Agent 框架。已有 Pi Agent 和 thinkEngine 可暂作为原生工具协议/传统文本协议两种适配，**不能各自拥有另一套任务状态、写入确认、证据和结果保存**。复用 ai/orchestrator.ts 的位置来承担真正入口；先让 AiPanel、autoThink 等实际调用它，再删除被取代的生命周期代码。voiceAnalysis 保留确定性的分块业务流程，使用相同运行上下文和底层流接口，不把每个评论分块变成 Agent。

~~~text
AiPanel / 原声任务 / 自动巡视
           ↓ 固定任务上下文与输入版本
唯一运行生命周期（队列、runId、取消、断点、结果）
           ↓
任务需要模型？ 否 → 现有规则/SQL工具直接算
              是 → 已有 Pi / 传统协议适配（同一权限与预算）
           ↓
Manifest白名单业务工具 → 结构化事实与证据 → 数值守恒检查
           ↓ 可选的公开资料缺口
Rust受控外发 → 不可信公开资料 → 本地归纳
           ↓
结论 / 计算 / 缺口 / 工具轨迹 / 来源版本
           ↓
用户保存成果 / 确认草稿措施；正式事实仍由业务页确认
~~~

[事实] 现状线索见第2章：orchestrator 尚未成为生产主入口，Pi 有工具串行和白名单，传统 loop 有轮数/空闲超时，原声有分块指纹。不要把这些已有能力整套重写。

### 7.2 最小运行上下文与状态

复用 ai_analysis_runs，补少量字段或一个带 schemaVersion 的 context_json/checkpoint_json/result_json，避免十几张新表：

- runId、taskType、projectId、skuId、sessionId、assistantMessageId，在启动时固定。
- sourceVersionIds、inputFingerprint、promptVersion、toolSchemaVersion、modelName；读取“当前”时保存读到的值和来源时间。
- status、currentStep、startedAt、updatedAt、错误类别；已完成的只读工具结果摘要、证据引用和可重试块索引。
- 每个写入动作有独立 actionId 和来源预览哈希，确认前再核对对象/版本；相同动作重复执行不能重复加措施。

~~~text
queued → running → waiting_approval / paused
running → succeeded / partial / failed / cancelling
cancelling → cancelled（后端流已中止或明确不能立即停止）
paused/failed/cancelled → 校验输入 → 新尝试，从安全断点继续
应用重启时仍running → interrupted，用户选择恢复或关闭
~~~

只读任务可以基于固定旧快照继续并标旧；任何正式写入都必须重新读取/比对现状。缺指纹的旧运行不能按“评论数量相同”继续。最后一块结束、保存主题前再检查取消状态和输入版本。

不保存模型内部思维链。可恢复的是计划摘要、已完成工具与结果、下一步和用户决定；不能靠重放隐式思考恢复。

### 7.3 工具、计算、证据

| 能力 | 最小设计 | 复用处与当前差距 |
|---|---|---|
| 明确任务/计划 | 展示“比较本项目与上代，核查规格和成本变化”；规则任务直接列2–4步 | AiPanel 和现有任务路由；不再为简单汇总让模型多轮规划 |
| 工具选择 | 按任务选相关 Manifest；参数化查询，最多返回所需行/聚合，明示截断 | toolRegistry/aiTools；STRUCTURED 子集逐步补全，context 不能传空 |
| 查询权限 | 默认本项目/SKU/选定版本；跨项目比较显式范围，返回每条来源 | AI 当前可读多个业务域，必须固定范围；不得让模型随意填另一项目覆盖运行上下文 |
| 数值核验 | amount、unit、scope、version、formula、inputEvidenceIds；关键结论由代码模板输出金额 | contracts 可扩现有字段；verifyConclusionNumbers 只保留为文本提醒，不作“核验通过”证明 |
| 证据 | 本地对象ID/字段/版本，公开URL/抓取时间；引用可点开 | 沿用 EvidenceRef；需要 bom/spec/target/quote/voice/run/artifact 类型 |

规则数值验证必须识别：A项目与B项目、元与万元、单价与行金额、BOM与标准成本、估计与确认、草稿与冻结。R08 的“20出现在120里”即使全文有数字，也完全不构成来源证据。用户提问中的金额只算用户提供的假设，云端文章里的数字只算公开资料，均不能自动升格为项目数据库事实。

证据被截断时保留可读摘要和完整本地引用，不把任意前4000字当全部事实。输出存在未解释残差/缺失价格时，明确降级部分结论，不能由模型补齐。

### 7.4 取消、恢复、超时与重试

1. 从用户点击停止到 UI 标“停止中”应即时发生；AbortSignal 必须贯穿执行器、工具、Ollama 监听与 Rust 网络流。Rust 按运行/请求 ID 取消实际请求，不只是退订事件。取消后禁止晚到结果保存正式产物，监听和句柄必须清理。
2. 设置无输出超时、单工具超时、单运行轮数/工具次数上限；预算触顶输出“部分完成，以下尚未完成”。不要把最后一轮片段包装完整答案。
3. 初始建议：一次只执行一个模型任务；交互任务优先于后台；自动只读请求遇短暂错误最多额外重试一次，失败交给用户。具体秒数/上下文上限通过本机测量设置，不能把 27B 的长首 token 等待误判网络故障。
4. 写工具不自动重试；先根据 actionId 查是否已提交。C2 请求发送后超时属于结果未知，不复用已消费授权重发。重试必须重新显示状态和再次批准新请求。
5. 切项目不改变运行归属；用户可以继续查看原项目运行或停止。恢复比较完整输入指纹，包括原声内容、模型/提示版本与工具版本，不只比较条数。
6. 使用明确消息 ID 更新输出，避免异步代码总写“最后一条助手消息”。失败日志不能 success=true。成功结果与失败块都能查看已完成工具。

### 7.5 自动巡视：先规则，后有需要才调用模型

复用 autoAdvisor + db/advisor；当前20个项目以内，普通规则不需要向量库、任务队列服务或复杂调度器。

- 每次数据事件登记 dirty 项目ID和原因；正在运行或冷却时不丢事件。前台空闲时按小批次处理。settings 中保存本地游标/最后完整扫描时间即可。
- 相同 issue_key + 相同语义 evidenceFingerprint 不通知；fingerprint只含判断所需事实和规则版本，不含 last_seen_at、展示排序等。
- 证据变化先更新卡片。用户忽略后，只有可解释的新事实/影响明显恶化才重开；轻微舍入变化不重开。金额门槛按本机实际工作校准，先用一个简单可调阈值，不建策略平台。
- 完整且成功扫描该范围后，条件已消失的旧问题置 resolved；数据读取失败/范围未扫描不自动关闭。
- recurrence次数/last_seen可更新，但不会触发“有新问题”。已转措施的发现引用同一措施，状态按关系展示，不再创建第二个待办。
- 不将行情下行直接等于量产降本额；需要项目当前生效价、对应物料映射、信号日期和上次有效谈价日期。
- 六类规则：新报价高于已确认可比基线、跨项目同规格价差、量产价未跟随行情、措施逾期、目标超标、距上次谈价过久。没有相应数据时是规则不适用/资料待补，不是没有问题。
- 多次出现相同项目/物料不同问题可以分别保留身份，但首页合并展示，避免六条提示表达同一谈价任务。

### 7.6 本机资源与性能边界

用户计划使用 Qwen3.8 27B、RTX 4500 24GB、128GB内存。**本轮未核验模型标签是否可用、量化/上下文配置、显存占用、首 token 时间、工具调用稳定性。** 不承诺这套硬件一定全量装入模型或达到某个 token/s。

Luna 应先在隔离数据下测三类任务：200行 BOM 对比、约1000条虚构评论分块、一次带工具的跨项目价差。记录模型精确标签、量化、上下文、首输出时间、总耗时、峰值显存、停止后资源释放、失败恢复位置。按测量调整现有配置，不先增加小模型、多卡或另一套 Agent。

流式文本先缓存在 ref，约50–100ms提交一次可见增量，完成时立刻flush；不要每个 token 让全聊天记录和Markdown重渲染。这是待测初值，不是已经达到的性能保证。

| 方案 | 价值 | 数据要求 | 复杂度 | 不做后果 |
|---|---|---|---|---|
| 统一运行生命周期 | 可停止、恢复、定位任务归属 | 少量run上下文和断点 | 中 | 多入口各有失败状态，错位写回难排查 |
| 结构化事实验证 | 数字可证明 | scope/unit/version/formula/evidence | 中 | 字符串检查继续放过假结论 |
| 巡视状态联动 | 安静且不漏真正变化 | 问题键、语义指纹、措施外键 | 中 | 同一事项反复提示或消失后常驻 |
| 单模型优先级 | 前台任务可预测 | 当前运行与待执行范围 | 低至中 | 后台分析抢占等待时间 |
| 结果契约 | 不靠聊天文本回忆依据 | 已有artifacts/证据引用 | 中 | 保存后的结论失去来源 |

## 8. 安全模型

### 8.1 威胁范围与已经做对的边界

[事实] Rust 已限制普通 HTTP 到回环地址，云端另有 HTTPS、端点校验、禁重定向、审批哈希和数据库票据，C2还校验正文并原子消费。前端 CSP 也不应按早期 AGENTS 的“开放”描述倒退处理。模型工具没有通用 SQL、Shell 或任意URL工具。

[推断] 仍需区分三个威胁层级：

1. **正常用户误操作/模型越权/恶意评论或搜索结果**：必须在业务工具与后端请求构造层阻止，不能只靠提示词和禁词。
2. **渲染进程被注入恶意代码**：当前 main 拥有 SQL execute/select，且可调用票据签发；后端从同一业务库查询票据并不证明用户同意。完整保护需要票据权威和秘密离开渲染层，显式人工审批采用可信后端/原生确认边界。
3. **本机OS账户/管理员或磁盘被完全控制**：当前登录页不是磁盘加密，portable数据库可被账户访问。本文不承诺应用能抵御OS完全失陷，也不以此为由放弃前两层。暂不引入全库加密和多人权限；如以后明确需要离线防盗，再单独设计备份/恢复与便携取舍。

不得读取正式凭据来演示风险。本轮只读源码，没有点击显示密码，也没有真实外发测试。

### 8.2 数据与工具权限表

### 8.3 完整请求由谁构造

目标数据流：

~~~text
本地敏感事实 → 本地规则/模型 → 公开查询意图DTO
→ Rust根据providerId、模板、公开词条构造最终请求
→ 严格类型/字段/端点校验 → 展示业务载荷与目标
→ 有效政策/单次审批 → 后端注入凭据 → 发送
→ 保存非秘密请求内容与状态/Hash → 返回不可信资料
→ 本地工具核验与引用；不能因云端文字自动写库
~~~

现状 request.headers 在 lib.rs:1524 被逐项转发；C1的一些允许参数只有键名约束。即使 q 被精确绑定，调用者仍可能把虚构敏感标记放在 X-Note 或 gl/hl 等参数值中。这是源码风险推断，**没有实际发送，也不声称已有泄露事件**。

最小修复：

- 保留一个 Rust 云端出口，把现有供应商适配迁入/约束在该出口。输入仅 providerId、capability、typed payload、authorizationId；URL/path/method/headers/固定搜索参数由已注册适配器决定。
- C1各字段用枚举/常量/长度/范围校验。禁止未知字段、重复query键、userinfo、片段、任意重定向及未注册端点；不依赖不断扩大的敏感词表。公开问题优先模板，开放文本必须降级逐次预览且不得带内部事实。
- 凭据来自后端 credentialId，不从前端传 Authorization / api_key / 任意header。少数服务需要把key放query或body时也由后端生成，日志掩码。凭据语法字段也不能被当成任意数据通道。
- 限定请求大小、响应大小、超时；读取响应达到上限即停止并显示截断，不能先无限 bytes() 再截断。保留搜索所需能力，不全面禁公开型号。
- loopback也应限制已配置的Ollama服务和必要路径；“是127.0.0.1”不等于“是Ollama”。模型不获得访问其他本地服务的通用能力。

不一次迁移所有业务SQL到Rust；先让秘密、授权权威和网络请求构造不受业务库通用写权限支配。

### 8.4 审批对象、生命周期与复用

批准的对象是**最终可复现的请求描述**：供应商/端点/能力/方法/允许字段与值/模板版本/作用域/有效期/次数。不是“我同意查一下行情”或 reviewed=true。

| 项目 | C1 / C1_PUBLIC_MODEL | C2 |
|---|---|---|
| 首次确认 | 供应商、能力、允许的词条/模板与日志范围；明确可随时撤销 | 本次实际脱敏字段、值、目标供应商和用途 |
| 生命周期建议 | 会话内默认最多30分钟；后台定期查需独立可撤销的有限政策，不默认为无限授权 | 默认5分钟待发送，成功取得发送权即单次消费；保留现有原子防重放 |
| 可复用条件 | 同政策、同provider/endpoint/模板版本、仅明确授权的公开词条；每次仍生成受控请求 | 不复用 |
| 必须重新批准 | provider/endpoint/方法/字段类型/模板变化，新增未授权公开型号，自由问题越范围，撤销/过期 | 正文、问题、档位、目标或系统模板任何变化 |
| 失败处理 | 超时提示本地结论仍可用；在政策内重试只读一次 | 发送前失败可明确重试；已消费后超时为结果未知，重发必须新票据 |
| 队列身份 | 保留当前精确主题+端点去重；政策内自动不反复入队 | 按最终payloadHash+端点+模板版本去重，不合并不同正文 |
| UI | 安全状态图标/外发记录；新权限一次审查，不每次弹窗 | 待确认栏查看实际内容，当前本地任务继续 |

授权权威建议存后端内存状态（短票据）或后端私有凭据域；业务DB只保存审计投影，不能靠INSERT一行获得授权。持久政策由可信确认动作创建，不能由模型工具创建。面对恶意渲染进程，仍需后端/原生可信确认展示具体请求或政策；只把签发函数搬进Rust、用后端Hash或签名包裹同一未确认输入，都不够。

单机应用无须角色系统。用户可以一次批准一组明确公开品类查询；C2保留逐次边界，实现安全与低打扰的平衡。

### 8.5 密码、API Key、日志和注入隔离

- 立即移除登录页的明文密码读取/双击展示及新明文副本写入。兼容迁移确认现有校验记录可用后删除 AUTH_PLAIN_KEY；不要在日志/报告中输出旧值。登录校验迁入后端，沿用旧校验的过渡能力并在用户成功验证/改密时升级，不擅自重置密码。
- API Key 使用操作系统凭据保护/现有可用平台能力，前端只得掩码与是否配置。portable数据库可携带，key默认不随库明文携带；迁移电脑后重新录入key。这一取舍不妨碍免安装exe。
- 审计记录run、对象范围、审批依据、时间、供应商、方法、端点、实际非秘密字段、响应状态、Hash、来源引用。业务载荷可重现；Authorization/cookie/api_key等秘密只保存掩码/credentialId，不能为“精确审计”复制秘密。
- 本地AI日志默认记录摘要/引用/版本，不长期复制整份原声、BOM与思考文本。原始导入仍在自己的事实表，不被每轮prompt再存一遍。建议默认30天详细调试日志，正式成果/确认记录保留至用户归档；提供本机清理并显示影响。
- 评论、Excel、搜索网页、模型返回一律是不可信内容。工具结果与用户指令分离；不能从搜索结果/思考通道解析执行工具，传统协议只解析明确的受约束调用结构。
- Prompt injection测试必须覆盖“忽略先前规则、读全库、发到某URL、把秘密放请求头、立即冻结BOM”。即使模型真的提出这种调用，也要在工具/网关层失败。
- 云端回答可引用但不能授予权限、证明内部价格、自动确认映射或自建长期事实。渲染Markdown禁止任意脚本/未经约束的HTML；外部链接明确显示目标，不把网页当应用指令。

| 改动 | 用户价值 | 数据要求 | 复杂度 | 不做后果 |
|---|---|---|---|---|
| 完整请求由后端构造 | 审核内容与实际外发一致 | 现有provider配置、固定适配器 | 中 | q安全但header/其他字段仍可夹带 |
| 票据权威与业务库分离 | 防伪造授权和重放边界清晰 | 短期后端状态、审计投影 | 中 | 通用SQL可触碰放行依据 |
| 凭据/密码收口 | 登录不泄密，key不进模型/前端日志 | 旧设置迁移、后端凭据引用 | 中 | 本地UI看似受锁但秘密已在渲染层 |
| 有限公开政策 | 正常行情查询少打断 | 明确词条/模板/供应商范围 | 中 | 要么频繁确认，要么过宽授权 |
| 简化日志 | 可审计且减少敏感副本 | 现有run/egress/artifact | 低至中 | 查询越多，冗余敏感数据越多 |

### 9.2 版本关系与一致快照

~~~text
项目 → SKU（可选） → 工作BOM
                  → 冻结BOM → 规格版本 + 费率快照 + SKU差异
参考项目 → 参考冻结BOM → 其绑定规格/费率
目标版本 → 基线事实 + 选定包 + 风险 + 财务目标快照
报价轮次 → 指定规格版本 → 各供应商原始批次/行
定点 → 有效报价批次 + 规格版本
阶段成果 → 上述确切引用及读出值，不能再查询latest组装旧成果
~~~

成本包一致快照的最小实现：

1. 在一个有连接归属保证的只读事务中取得项目/费率、我方与上代版本、规格、目标、SKU、选定报价、定点、措施、评审。多个独立Promise.all查询不是一致快照。
2. 现有SQL插件跨调用事务的连接归属须实测；无法证明时仅将冻结/生成快照做成一个Rust命令，在同一连接事务完成，不迁移全部CRUD。
3. 形成不可变snapshot DTO，统一计算source manifest。至少含项目/参考元数据、BOM/规格/SKU/目标、费率、有效报价批次及匹配、定点、措施/评审、算法版本。
4. 预览、导出、成果保存使用同份DTO和hash，不能另用props、latest或静默fallback。
5. 新鲜度复用同一个manifest构造函数。读取失败=unknown；有差异=stale并说明变化项。冻结结果永远是当时快照，过期仅表示不能代表现在。

不建立全库版本系统；冻结ID+规范序列化来源值+算法版本足够。Hash用于识别变化，不替代事务、鉴权或业务可比性。

### 9.3 状态与迁移

| 对象 | 状态与守卫 |
|---|---|
| BOM | 工作数据可编辑，冻结不可编辑；被取代不使旧事实变草稿；冻结检查缺价、金额、规格引用并人工确认 |
| 目标 | draft→previewed→confirmed/frozen→superseded；来源变化使预览失效；旧版保留原算法及缺口 |
| 包 | candidate/draft→feasibility_confirmed→selected→implemented或rejected；实施必须有结果事实 |
| 轮次/报价 | 人工创建轮次，确认批次不可覆盖；修订新批次，有效选择集排除失效批次 |
| 主题 | AI候选与人工决定并存；改名稳定ID，合并/归档明确操作，重跑不删除 |
| 巡视 | open→acknowledged/linked_measure/dismissed/resolved；语义新证据才reopen，失败扫描不resolve |
| 成果 | draft/formal是内容状态；current/stale/unknown是新鲜度，不能混为一个字段 |
| 运行/授权 | 使用第7、8章状态；正式写入不自动重试；消费后的C2不复用 |

迁移只在隔离库先试，重复运行幂等。关键表/列失败应阻止相应正式功能，不能被通用ignoreSchemaError吞掉再标ready。不把缺失填0，不把旧草稿标冻结，不按日期筛今日行补历史。保留旧ID/JSON原文，用schemaVersion区分解释；外键检查项目/SKU作用域。建立唯一约束前先识别重复，保存合并映射。新增必要核心类型覆盖查询字段，不全仓重写类型。

Luna实施重要变化后同步AGENTS和新的验收记录；本设计审计不覆盖旧报告的历史证据。

### 11.2 P0：数据和安全错误

#### P0-01 移除登录前明文密码

- 问题/影响/根因：LoginScreen登录前加载真实密码，Logo可展示；auth保存明文副本，登录锁失去意义。
- 最小改动：删除展示与明文读取/新增写入；兼容现有校验，迁移验证后删除AUTH_PLAIN_KEY；校验和改密逐步归后端，禁止输出旧秘密。
- 文件/数据：src/pages/LoginScreen.tsx、src/db/auth.ts、src/db/core.ts、必要Rust命令。数据为既有校验记录，复杂度低至中；迁移不得重置密码或影响正式业务表。
- 验收/正反测试：正确旧密码仍能验证；错误密码失败；升级前后旧明文值不进入前端/日志；迁移中断不锁死已有用户；双击无秘密显示。
- 桌面：需要手动登录隔离副本；隔离库：必须。不要顺手重做登录品牌/账户系统。
- 不做后果：登录前即可取到本机密码。依赖：无。

#### P0-02 将API Key移出渲染层

- 问题/根因：provider设置以明文字段读写，前端适配器拼认证信息；有泄露到UI/日志/模型的风险。
- 最小改动：后端credentialId读写，前端仅掩码/状态；使用平台凭据保护；旧key成功迁移后再删除旧副本，失败保持可恢复且不报告成功。
- 文件/数据：src/db/settings.ts、src/trendService.ts、src-tauri/src/lib.rs、provider设置组件；数据为provider与凭据引用，复杂度中。先用rg定位所有api_key读取者，覆盖搜索和C2。
- 验收/正反测试：虚构key正确用于替身请求；业务SQL/前端配置读取只有掩码；错误凭据/迁移失败有提示；日志无key；换电脑显示需重新录入。
- 桌面：需要设置页；隔离库/虚构key：必须。禁止真实连接测试；不加云同步或全库加密。
- 不做后果：凭据继续被渲染代码和日志接触。依赖：不依赖业务金额票，可单独做。

#### P0-03 后端构造并校验完整云端请求

- 问题/根因：q已绑定但headers及部分参数值可由前端自由提供。
- 最小改动：将现有provider适配收口为后端typed请求；固定URL/method/header/搜索参数，凭据后端注入；拒绝未知/重复字段，限制请求/响应体及超时。
- 文件/数据：src-tauri/src/lib.rs、src/trendService.ts、src/ai/security.ts、src/ai/c2Bridge.ts；数据用现有provider与模板，复杂度中，迁移仅适配器配置版本。
- 验收/正反测试：合法通用品类/公开型号/C2替身请求构造正确；虚构敏感标记放q、gl、headers、body未知字段均拒绝；重复query、换端点、重定向、大响应失败；已有C1追加q/C2测试仍过。
- 桌面：实际外发预览需要；隔离库与HTTP替身：必须。不得为测试放宽生产allowlist，不全面禁公开型号，不新增通用HTTP工具。
- 不做后果：审批内容与实际请求不等价。依赖：P0-02；可先实现不含凭据的纯请求构造测试。

#### P0-04 授权权威、单次消费和低打扰复用

- 问题/根因：业务库票据与main的通用SQL权限同域；签发命令不能单凭前端调用证明人工同意。
- 最小改动：短票据权威移后端，业务库只留审计；新政策/单次C2走可信确认；C1有限公开模板政策可复用，C2保留原子消费，端点/正文变化重批；查询排除已消费票据。
- 文件/数据：src-tauri/src/lib.rs、src/db/ai.ts、src/cloudConfirm.tsx、确认栏组件；数据为旧票据/政策，复杂度中。旧授权失效提示重批，不转成宽授权。
- 验收/正反测试：业务库伪造ticket不能放行；相同C1政策内重复查询不重复弹；撤销/过期/改模板失败；C2并发最多一次，超时重发需新批准；拒绝敏感意图。
- 桌面：需要可信确认/队列；隔离库与无网络替身：必须。不要建RBAC、组织审批或“万能同意”开关。
- 不做后果：后端hash被误认为人工授权证据，日常体验仍在过严/过松间摇摆。依赖：P0-03。

#### P0-05 统一金额、数量与缺失语义

- 问题/根因：part_cost>0才取项目价、cost单价/行金额混用、quantity||1、缺失强转0；影响BOM/目标/报价/报告/AI。
- 最小改动：复用contracts的行金额函数建立唯一口径，补priceState/domain/part_specs读取；明确0、缺失、负数规则和历史字段解释。只对业务真实允许的0参与计算。
- 文件/数据：src/ai/contracts.ts、src/db/projects.ts、src/db/architecture.ts、src/db/core.ts、src/types.ts及其真实调用者；数据为行来源/字段状态，复杂度中；旧未知不自动回填成已确认。
- 验收/正反测试：数量2×单价10=20；已确认零价=0；缺价=未知而非0；qty0不变1，负数量阻止正式冻结；主库价格改动不改变已确认项目快照；重复行全保留。
- 桌面：需要BOM导入和手改；隔离库：必须。不要改利润/税务模型或全仓重构。
- 不做后果：所有上层金额仍可能错。依赖：无，是数字路线底座。

#### P0-06 冻结事实、历史明细和成本包一致性

- 问题/根因：冻结行缺领域/规格引用；旧快照查今日行；阶段包费率取props，多次独立读取不一致。
- 最小改动：统一冻结/读取快照；补规格、费率、领域与来源关系；旧快照只读已有汇总。预览/导出/成果fingerprint共用DTO，明确读取失败/草稿/未知；不要静默重算替换已确认预览。
- 文件/数据：src/db/architecture.ts、src/db/projects.ts、src/components/CostPackageButton.tsx、src/db/artifacts.ts、src/db/core.ts；同连接事务无法由现有插件保证时增加一个专用Rust命令。复杂度中偏高，分“事实快照”与“报告接入”两个连续小提交。
- 验收/正反测试：R05/R06/R09修正；领域和标准成本守恒；上代/当前版本绑定；导出前改价/费率不会混快照；当前空BOM不回旧缓存；缺历史规格显示未知；注入中途读取失败不产生正式包。
- 桌面：冻结/预览/导出需要；隔离库：必须。不重写全部SQL层，不删除旧快照，不先美化PPT。
- 不做后果：正式报告可能历史漂移或总额/领域相互矛盾。依赖：P0-05。

#### P0-07 目标按完整依赖包守恒

- 问题/根因：净节省分给正领域、按比例切挑战、空证据仍可入目标，实际由目标倒推。
- 最小改动：保留包的领域有符号向量，整包选择；基线先核对行/模块/规格适用范围，不能将模块最低值压到整个领域；已实现/无依据/互斥冲突不入未来机会；未覆盖缺口保留。目标预览绑定事实hash，确认同份结果；实际独立读取。
- 文件/数据：src/db/architecture.ts、src/components/CostPlanningWorkspace.tsx、src/db/core.ts、目标类型；数据为包来源/领域/实施状态，复杂度中，旧目标保留旧算法版本。
- 验收/正反测试：R01得到80/20或100/5，不得95/5；R02待补；第6.4例640.50与缺口10.50；已入基线不再扣；模块基线不得替代整领域基线，不可比历史低价不得生效；包包含增成本领域；依据变化预览失效；风险不写实际。
- 桌面：目标预览/确认需要；隔离库：必须。不建优化求解器，不为凑目标加比例滑块。
- 不做后果：目标总额正确但领域无法交付。依赖：P0-05/06。

#### P0-08 报价矩阵不丢行且口径一致

### 11.6 暂缓与待确认事项

明确不做：多人角色、组织权限、云同步、生产库存良率、物流税务、通用流程引擎、多Agent协商、向量库、无数据支撑的预测/箱线、复杂供应商评级、全功能Excel猜表、主题编辑器。没有这些也能完成用户的ODM成本工作。

仅以下问题可能改变后续细节，不阻塞P0：

| 问题 | 本文默认 | 何时再确认 |
|---|---|---|
| 平台费是否存在固定额或特殊基数 | 现有百分比，基于物料+包装+ODM加工 | 遇到真实合同差异时，不先扩费率引擎 |
| 财务目标是否需按SKU分别给 | 项目财务输入为主，SKU单独显示事实与差额；未给目标不继承装成确认 | 开始做SKU阶段包前确认 |
| 风险准备是否纳入承诺目标 | 同屏双口径，默认可行目标与风险准备分列，由人选承诺边界 | 冻结第一个实际目标版本时 |
| 登录是否承担离线文件防盗 | 定位为界面锁；API Key后端保护；全库加密暂不做 | 用户明确要求磁盘文件保密时单独设计 |
| 实际模型精确标签/量化/上下文 | 使用用户选择的本地Ollama模型，不承诺尚未实测配置 | P1-03实机测量前 |
| 老数据中0/旧cost含义 | 保留原文并标未知，不自动当免费或缺价 | 在隔离旧库查看真实导入来源后，由用户确认 |

### 11.7 每轮复核完成的共同标准

“完成一票”需要：最小虚构反例先失败、修复后通过；相关旧回归通过；迁移幂等；行为/数字/状态能解释；桌面需要而尚未做的明确写未验证。不要用构建成功替代业务验收，也不要通过删测试或放松校验让结果变绿。

每轮交付修改范围、原因、正反样例结果、迁移/兼容、桌面证据、未验证范围；指出是否改变本报告中的源码行号和旧结论。只要尚有关键未验证范围，就不能写“全链路完成”。
