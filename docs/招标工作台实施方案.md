# 招标工作台实施方案

## 1. 目标与边界

招标工作台服务于 CDCP 前的整机 ODM 招标：在不改变现有器件库、项目 BOM、成本评审和报告流程的前提下，增加报价批次、规格基线、供应商横向比价、理论组合底价和议价依据。

首期只做本地能力：Excel 报价导入、规格/轮次/批次留痕、报价矩阵、同名同规格的可比标记、理论组合底价和过程事件。导入报价不会自动覆盖项目 BOM，也不会自动选择供应商。

“理论组合底价”是从各供应商可比报价中取出的最低单价之和，仅作为谈判锚点，不代表实际采购篮子、供应商承诺或最终成本。

## 2. 目录结构

```text
src/
├─ tenderImport.ts                 # Excel 解析、表头识别、报价行标准化
├─ db/
│  ├─ core.ts                      # 招标域表结构初始化与索引
│  └─ tender.ts                    # 招标域查询、导入、匹配、过程事件
├─ components/
│  └─ TenderWorkspace.tsx           # 项目详情中的招标工作台
├─ pages/Projects.tsx              # 工作台入口（保留原有 BOM 页签）
└─ aiSkills.ts / aiTools.ts        # 本地模型的招标分析能力
docs/
└─ 招标工作台实施方案.md
```

## 3. 数据模型

| 表 | 职责 | 关键约束 |
|---|---|---|
| `project_spec_baselines` | 被报价或里程碑引用的规格快照 | 版本号递增；保存完整 JSON 与变更字段 |
| `tender_rounds` | 一次招标阶段/轮次 | 关联项目和规格基线；按 id 倒序取当前轮次 |
| `supplier_quote_batches` | 某供应商某轮次的一份报价文件 | 文件哈希去重；保存币种、税制、报价方式和总价 |
| `supplier_quote_lines` | 报价文件的原始明细行 | 保留原始字段和 `raw_json`；不覆盖 `parts`/`project_boms` |
| `quote_line_matches` | 人工或规则匹配历史 | `exact/equivalent/reference/incomparable/unmatched`；可追溯来源 |
| `project_process_events` | 自动过程日志 | 导入、规格冻结、确认、定标、复盘等事件 |
| `negotiation_items` | 从可比价差沉淀的议价线索 | 可重复生成；状态可跟踪，不等于采购指令 |
| `tender_decisions` | 最终定点与复盘摘要 | 每项目一条，可保存草稿/已定点/取消 |

报价默认口径为人民币、未税、一次性报价；数量阶梯作为原始备注保留，不参与首期底价计算。

## 4. 接口定义

前端通过 `src/db/tender.ts` 调用以下接口，全部使用参数化 SQL：

```ts
importTenderQuoteBatch(input: ImportTenderQuoteInput): Promise<{
  batchId: number; roundId: number; specBaselineId: number;
  duplicate: boolean; importedLines: number; roundLabel: string;
}>;
getTenderOverview(projectId: number): Promise<TenderOverview>;
getTenderMatrix(projectId: number): Promise<TenderMatrixRow[]>;
getTenderQuoteBatches(projectId: number): Promise<QuoteBatch[]>;
updateTenderLineMatch(lineId: number, relation: MatchRelation, confidence?: number, remark?: string): Promise<void>;
recordTenderEvent(projectId: number, eventType: string, summary: string, detail?: string): Promise<number>;
saveNegotiationItems(projectId: number, items: NegotiationItemInput[]): Promise<number>;
getNegotiationItems(projectId: number): Promise<NegotiationItem[]>;
updateNegotiationItemStatus(id: number, status: 'draft'|'sent'|'agreed'|'closed'): Promise<void>;
getTenderDecision(projectId: number): Promise<TenderDecision | null>;
saveTenderDecision(projectId: number, input: TenderDecisionInput): Promise<number>;
```

`ImportTenderQuoteInput` 最少包含项目、供应商、文件名、文件哈希和标准化报价行；每行必须保留来源行号、原始名称/型号/规格、数量、单价和原始 JSON。

## 5. 组件职责与交互

### `tenderImport.ts`

- 支持 xlsx/xls，前 15 行自动探测表头和中英文别名。
- 解析模块、名称、型号、规格、数量、单价、小计、备注。
- 计算标准化 `canonical_key`，只用于分组，不宣称物料等价。
- 生成文件哈希用于幂等导入；不联网、不调用 AI。

### `TenderWorkspace.tsx`

- 顶部显示当前轮次、规格版本、供应商数、可比覆盖率和底价。
- 主操作只有“导入报价”“查看比价”“生成议价清单”三类，导入采用预览确认，缺供应商名时只问一次。
- 矩阵默认展示各供应商最新批次；列为供应商报价、可比最低、机会金额。
- 筛选支持全部、仅有机会、待确认；历史批次在抽屉查看，不打散主页面。
- 明确展示“理论组合底价/谈判锚点”标签，避免误读成采购方案。
- 报价行详情可直接确认匹配关系；历史批次抽屉和过程时间线集中展示版本变化，确认后保留原始报价并刷新矩阵。
- “生成议价清单”会把机会项本地沉淀为可跟踪草稿并同时导出 Excel；“定点与复盘”折叠区记录最终供应商、整机报价、依据和复盘摘要。

### `Projects.tsx`

新增“招标工作台”页签，但默认仍打开原 BOM 页签，原有 BOM 导入、编辑和成本计算路径不变。

## 6. 过程版本规则

规格只有在首次导入报价或进入新轮次时形成基线；项目当前编辑中的规格仍属于草稿。规格基线通过完整 JSON 指纹和 `changed_fields_json` 表达变化，不要求用户手工维护版本号。重复文件按项目+文件哈希拦截，允许用户重新选择不同文件后继续。

报价原文永不被覆盖。重新报价只新增批次；矩阵读取当前轮次每家供应商最新批次，历史从批次抽屉进入。确认匹配会新增匹配历史并更新当前状态，不删除原始关系。

## 7. 验收标准

### 功能

1. 从项目详情进入工作台不影响现有七个页签和默认 BOM 操作。
2. 拖入一份报价 Excel 后能预览行数、供应商和报价口径；确认后显示批次和矩阵。
3. 同一项目重复导入相同文件哈希不会产生第二个批次。
4. 多供应商同名同规格行能汇总到同一矩阵行；待确认行不会计入理论组合底价。
5. 理论组合底价、最佳整机报价、机会金额均能追溯到供应商和来源批次。
6. 规格变化、轮次变化、导入和匹配确认均出现在过程事件中。
7. 生成议价清单后可在工作台恢复查看并更新状态；定点/复盘记录可保存、重开项目后恢复。

### 安全

1. 报价原文和数据库只在本机 SQLite 保存；解析器没有网络代码。
2. 工作台不把报价数据放入外部 URL、日志、遥测或默认云端模型请求。
3. 本地 AI 仅通过 allowlist 工具读取聚合数据；任何云端调用必须经过 Rust 控制网关、脱敏预览和条件审批。
4. 所有写操作可从事件日志追溯，禁止静默删除和静默覆盖。

### 体验与性能

1. 常见导入路径不超过“选择文件→预览→确认”三步；缺少供应商名才增加一次输入。
2. 宽矩阵支持横向滚动，首列和汇总列固定；空数据提供直接导入入口。
3. 1000 行报价导入后界面可用，矩阵加载不阻塞项目详情其他页签。
4. 动效关闭时弹窗、下拉框仍可见；遵循系统 reduced-motion 设置。

## 8. 禁止事项

- 禁止把报价导入直接写入当前项目 BOM 或覆盖器件库价格。
- 禁止仅凭名称相似自动认定同一物料；等价、参考和不可比必须可区分并可人工确认。
- 禁止把跨供应商最低价拼成“实际采购清单”或直接替代最终供应商报价。
- 禁止为了展示历史而在一个表格中覆盖旧版本；必须新增批次并保留原始数据。
- 禁止在前端直连外网、把原始报价发送到云端模型或在错误日志打印报价明细。
- 禁止增加强制复杂表单、改变既有 BOM 入口、移除密码找回机制或破坏单机离线使用。
- 禁止把“已沉淀议价清单”或“已定点”状态当作采购订单或自动改价指令。

## 9. 发布与回滚

首期变更只新增表、接口、页签和本地 AI 工具。发布前运行前端测试、TypeScript 检查、Vite 构建和 Tauri 检查；若工作台异常，可隐藏新页签，原有 BOM/器件库仍可独立使用。数据库新表采用 `CREATE TABLE IF NOT EXISTS`，不修改既有数据结构，便于回滚二进制而保留已导入批次。
