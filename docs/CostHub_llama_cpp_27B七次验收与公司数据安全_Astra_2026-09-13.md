# CostHub 七次验收：公司电脑部署与数据安全

日期：2026-09-13。初始检查对象为当前工作区 v2.3.19；未读取公司数据，未向云端发送测试内容，未更改公司设备策略。初始记录发现三个 P1，随后按本报告完成返修、回归和重新打包。

## 结论

普通功能已达到可带到公司电脑做本地样例试用的程度，但按“公司数据不得外发”的要求，当前默认配置不予正式放行。先补齐下面两个部署边界及一个网关校验缺口，再投入正式数据。若公司 IT 已在系统层落实并验证应用及模型进程禁止外联、保留本机回环，可以在该边界内先试用；不能把“公司网络有管控”直接等同于已经满足这一条件。

27B 的真实速度、长上下文、工具选择质量和 mmproj 仍未在目标机器实测。本轮通过不代表这些指标通过。

## 必须收口的项目

### 1. P1：缺少后端强制纯本地模式

位置：`src/components/CloudPolicyControl.tsx`、`src/cloudConfirm.tsx:214`、`src-tauri/src/lib.rs:2782`。

目前只有 preview / auto。preview 也会复用已存在、未过期的精确授权；两者均不是关闭外发。Rust 会校验票据和端点，但未见“公司纯本地”总开关。正常配置下没有证据表明应用正在自动泄露，但不能据此满足禁止外发的部署要求。

最小改造：复用设置入口增加纯本地选项，由 Rust 在云端授权签发、实际请求发送前统一拒绝；设置读取失败时拒绝云端发送。前端隐藏/禁用云端工具并停止相应排队，避免本地分析不断出现审批提示。旧授权不能绕过此模式。保留本地模型、数据库查询、Excel、计算、图表、任务文件、会话恢复；业务写入继续沿用原确认门禁，无须每次读取都弹窗。

### 2. P1：llama.cpp 回环检查不等于模型进程禁止外联

位置：`src-tauri/src/lib.rs:344`、`:2817`、`:2932`；`src/components/LocalAISecurityStatus.tsx:45`。

托管服务确实只监听 127.0.0.1；CostHub 的本地 HTTP 也禁止代理和重定向。但 llama.cpp 分支跳过 Ollama 的出站防火墙验证，模型是普通进程启动；界面仅依据后端类型就显示绿色“已通过”。这验证了访问地址的限制，没有验证 llama-server 的出站隔离。未发现其实际外发的证据。

最小改造：分开展示“仅本机访问”与“进程外联隔离”状态。公司部署由 IT 一次性配置并验证 CostHub、实际 llama-server 路径及相关进程的外联限制，保留回环；不要让用户每轮确认，也不要在公司电脑绕过权限或自行提权。若程序承担验证，应按实际进程/路径验证，不能相信前端传入的 backend 字符串，也不能只按文件名认定可信。

### 3. P1：C1 非查询参数可夹带未审批文本，已复现

位置：`src-tauri/src/lib.rs:2212`、`:2274`、`:2358`。

查询词 q/query 已与授权内容严格绑定，但部分其余字段只检查名称、没有约束值。例如已批准 `MLCC 公开行情`，保持 q 不变，在 JSON 的 hl 或 URL 的 hl 参数放入虚构字符串 `COSTHUB_DUMMY_SECRET_12345`，完整 `validate_cloud_request_with_grant_at_path` 均返回 Ok。

这证明后端授权边界可被构造请求绕过；不表示当前正常搜索适配器已经在发送这样的内容，也未证明普通模型可直接设置 hl。请求即使最终被第三方拒绝，其字节也已到达第三方，所以不能以参数无效作为保密措施。

最小改造：在共有 Rust 校验入口约束所有可外发字段的类型、范围、枚举及嵌套结构；更稳妥的是由后端依据已批准主题和固定提供商参数组装请求。凭据字段仅接受后端注入。不能只给 hl 加一个敏感词正则。纯本地模式可先切断此出口，但启用云端前仍需修复。

已将复现断言加入 `src-tauri/src/review_round3_test.rs`。修复后必须通过：

```powershell
cd src-tauri
cargo test --lib review_c1_scope_must_not_accept_appended_private_text -- --nocapture
```

当前结果：失败；body=Ok、url=Ok。本测试使用临时数据库和虚构数据，未执行 HTTP 请求。保留失败断言作为返修验收标准。

## 已有防护和本轮验证

| 边界 | 检查结果与限度 |
| --- | --- |
| 本地 HTTP | Rust 只允许回环，localhost 规范化为 127.0.0.1；关闭代理及重定向。不是对任意本机服务的身份认证。 |
| 页面资源 | 生产 CSP 禁止直接访问外部接口和远程图片，禁用 object、表单外发。用户主动打开外部链接会进入外部浏览器，应受公司系统策略约束。 |
| 云端 | HTTPS/域名白名单、真实数据库票据、端点与方法绑定、到期/撤销校验；C2 正文哈希及单次消费。非查询参数仍有上述缺口。 |
| 密钥 | Windows DPAPI 保存提供商密钥，后端注入；仅接受固定 JSON 请求头。密钥保护不等于业务数据库加密。 |
| 工具文件 | 限制任务目录、检查路径越界，内置 Skills 只读；正式业务数据由专用工具读取，并非任意磁盘读取工具。 |
| 脚本 | 需要授权；Windows AppContainer 无网络能力、精简环境、实际 token 验证，失败拒绝执行。现有真实测试通过：用户目录哨兵读取被拒绝、本地监听器连接被拒绝。公司环境仍需现场自检。 |
| 会话与日志 | 保存本地对话、思考、工具参数/结果、恢复状态；长结果和附件还会保存在任务目录。它们也是公司数据，不应随支持包带出。 |

本轮测试：

- `npm test`：66 个文件，378 通过，2 跳过。
- 扩充安全断言前 `cargo test --lib`：20 通过；扩充后针对性用例失败，见上文。不能把当前版本描述为安全测试全绿。
- `node docs/check-local-settings-acceptance.cjs`：通过。验证外部回环地址不被非端口设置覆盖、未配置温度不被默认保存、旧探针结果丢弃、停止后迟到健康响应不恢复“服务可用”。第一次浏览器页面加载超时；Rust 编译结束后独立重跑通过。

## 不影响使用的后续完善

1. 保留本地日志和恢复证据，但明确其敏感性。删除会话目前删除数据库记录，不会同时清除任务文件；可增加用户主动选择的“同时清理附件和任务产物”，不要自动删掉用户成果。
2. “脱敏诊断”不是允许向公司外传输的依据。公司部署可仅在界面展示通过/失败及错误码；无需导出数据库、原始日志、截图或诊断文件给开发机。模型文件名本身也可能是内部信息。
3. 公司自检用内置虚构样例先跑：启动与停止、取消、多次工具调用、Excel 分页、计算、图表、重启恢复；再在公司电脑本地核对少量实际业务操作。结果留在公司，无须为了验收导出正式数据。
4. 发布时仅携带程序、可信运行依赖与批准的模型文件；不要复制开发目录中的数据库、授权数据库、日志、任务目录或带密钥的配置。部署目录避免个人网盘自动同步，遵循公司已有存储与备份规则。

完成上述三项后，以纯本地默认配置重新验收并打包。不能靠更多敏感词或更多弹窗承诺“绝不泄露”；把外发出口实际关闭，同时保留本地工具能力，才符合本次使用要求。

## P1 返修复核

### 纯本地模式

- cloud_network_mode 默认安全值为 local_only，保存于独立的 Rust 云端授权库；读取失败时按拒绝处理。
- Rust 在授权签发、有效授权读取、供应商云端请求发送前统一拦截纯本地模式；旧授权不能绕过。
- 设置页切换为纯本地时清空前端待确认队列、会话授权并撤销有效授权；云端确认入口和连接测试也在前端先停止。

### C1 网关字段

- 公开检索请求的非查询字段现在经过共享 Rust 校验：固定类型、枚举、数量范围和 contents.text.maxCharacters 结构。
- api_key 仅允许后端注入后的第二次校验通过；调用方自带凭据字段会被拒绝。
- review_c1_scope_must_not_accept_appended_private_text 已通过，覆盖 q 保持不变时在 JSON/URL 的 hl 侧信道注入。

### llama.cpp 网络状态

- 设置页拆分显示“仅本机访问”和“模型进程外联隔离”。
- llama.cpp 只显示回环访问已通过，进程外联隔离显示“待 IT 验证”，不再因 backend 类型直接显示绿色全通过。
- 本次没有替公司 IT 验证实际 llama-server 路径的系统防火墙/进程策略，也没有做全机流量证明；这仍是部署前现场检查项。
