### B06 / P1：新的 SQL IPC 没有保持事务连接归属

位置：`src-tauri/src/lib.rs:234` 创建最大 5 个连接的池；`:249` 的查询与 `:261` 的执行各自向连接池借连接。前端仍以多个独立 IPC 调用发送 `BEGIN → 查询/写入 → COMMIT/ROLLBACK`。

例如 `src/db/auth.ts:18` 的密码迁移、`src/db/projects.ts:127` 的成本快照，以及 architecture、dataImport、tender、voice 中的事务，都依赖这些调用属于同一个事务。

SQLite 事务属于连接。逐条向池提交 SQL，不能保证后续语句使用 BEGIN 所在连接；即使 ROLLBACK 成功，也可能只回滚了一个没有包含实际写入的事务。把连接数简单改为 1 也不能完整解决事务归属：其他业务调用仍可能插入同一个事务。

本轮用同版本 sqlx、相同逐调用 `execute(&pool)` 方式，在独立内存数据库内复现。`min_connections(2)` 用于模拟池已有两个活跃连接的状态，**并非通过真实桌面 IPC 重放**。结果：

```text
rollback_ok=true, rows_after_rollback=1
assertion failed: A transaction must roll back every write issued between BEGIN and ROLLBACK
```

最小源文件：`docs/review-astra-transaction-20260905.rs`。本机复现工程位于忽略目录 `src-tauri/target/review-transactions/`：

```powershell
cargo run --offline --manifest-path src-tauri/target/review-transactions/Cargo.toml --target-dir src-tauri/target
```

若在另一工作区重建，将该 `.rs` 复制为独立临时 Rust 工程的 `src/main.rs`，使用以下清单，并复制本仓库 `src-tauri/Cargo.lock` 到工程根目录以固定依赖（当前离线缓存有被撤回版本，裸解析可能失败）：

```toml
[package]
name = "costhub-transaction-probe"
version = "0.1.0"
edition = "2021"

[dependencies]
sqlx = { version = "0.8", default-features = false, features = ["runtime-tokio", "sqlite"] }
tokio = { version = "1", features = ["rt", "time", "net"] }
```

实施要求：让一个事务持有同一连接，并明确事务所有权；可将需要查询后决策的操作收进后端事务命令。只做写入批次的场景可用后端原子批处理。复用现有接口与数据模型，先梳理上述所有调用者，避免只修密码路径。

复验必须覆盖：中途失败后零残留、成功提交全部可见、两个并发业务不串事务、密码迁移失败保留恢复数据、冻结来源与快照一次性提交。原有模拟数据库测试不能代替实际连接池集成测试。

## 二、设计方向：精密的项目档案，有纸张触感的工作手记

高级感来自内容层级、材质分工与动作反馈。项目页面强调核对效率；手记页面允许表达个人判断和现场感。

本轮已完成两套完整页面及交互，入口：

- 本地预览：`http://127.0.0.1:5188/atelier.html`
- 可直接打开的文件：`prototypes/ui-review-20260905/atelier.html`
- 配套样式与交互：同目录 `atelier.css`、`atelier.js`
- 项目图：同目录 `project-1400.png`
- 手记图：同目录 `journal-1400.png`

全部数据为虚构。仅使用原生 HTML、CSS、JavaScript 和现有 Ant Design 图标的 SVG；无新增依赖、外部字体或外网请求。手记编辑保存在当次页面内存，刷新恢复示例。AI、导出和证据抽屉为交互预览，没有连接正式服务。

同目录 `index.html` 是前一版工作台对照稿。它用真实 DashboardRedesign JSX 和现有 CSS 加示例数据重建，侧栏、AI 状态和部分组件样式作了替身处理，不是运行中的桌面版截图。最终设计方向以 **atelier.html** 为准。

### 当前界面最值得优化的地方

现有工作台已经有清楚的业务分区，但大面积玻璃感、圆角卡片和彩色图标让区域权重接近，视线缺少明确落点。源码里还有 9–11px 的指标说明、按钮和元数据；数据密度应靠布局取得，而不是持续缩字。

保留五个主导航的业务结构与默认折叠的 AI 面板；原型只展示本轮重点页面，不能据此删除情报、工作台等入口。统一主题令牌后，逐页替换页面组织方式，避免不断在全局 CSS 尾部叠加覆盖。

同时修正文案与数据表现：金额保留两位小数；最近活动用实际时间；没有可量化进度时展示阶段和待办；“排序”必须说明实际排序依据。不要让视觉组件暗示不存在的趋势、完成率或精确性。

### 项目页：把成本核对做成主工作面

1. 页头固定项目身份、阶段、产品规格版本和两个主要操作。
2. 使用横向工作区页签：总览、BOM 与报价、目标与措施、版本档案。切换位置稳定。
3. 顶部成本摘要呈现当前标准成本、计算组成、财务目标、差额与来源状态。产品示意作为辅助识别，正式版优先使用已有产品图片。
4. 主区为领域对照表：当前 BOM、方案目标、差额、证据入口；金额右对齐、等宽数字，列宽稳定。
5. 右侧呈现一个优先决策，放在一起核对节省、必要增本、净影响与缺失证据。
6. 证据采用上下文抽屉，关闭后回到原表格位置。冻结版本保持只读语义。

示例守恒关系：当前 BOM 610.00，平台费 5%，标准成本 640.50；显示节省 20.00、驱动增本 15.00，BOM 净节省 5.00，实施后标准成本 635.25。距财务目标 630.00 仍差 5.25。尚未实施的机会不能覆盖当前事实。ODM 整机报价独立展示币种、税费、数量和交付条件，缺条件的报价保留“待补齐”。

### 手记页：文件夹负责找，纸面负责读

1. 文件夹是项目筛选入口，展示代号、产品类型与记录数。以现有项目关系分组，不新增实体文件系统或数据库表。
2. 桌面布局为左侧时间索引、右侧正文。支持摘要/紧凑列表，关键词搜索和明确空状态。
3. 正文使用温白纸面、细边线、轻微纸张层次；标题可以用本地宋体衬线，正文与所有业务表格继续用清楚的无衬线字体。
4. 贴纸承载跟进状态，正式实施必须映射现有状态字段或明确持久化语义。禁止只改变颜色却让用户误以为业务已完成。
5. 关联证据属于当前记录。没有关联时显示空态，不能复制上一条记录的证据。
6. 复用 WorkLog 现有记录类型、阶段、日期、项目、内容、影响、下一步、截止时间与证据字段。原型简化编辑器只演示视觉，不作为删减正式字段的授权。

文件夹数量多时，首页只呈现最近/关注项目，其余使用可搜索项目筛选。不要渲染数百个拟物文件夹挤掉正文。

## 三、实施规格

| 对象 | 规格 |
| --- | --- |
| 主色 | 克制的深松绿色；页面冷灰，正文暖白；正式令牌以 atelier.css 实际值为起点 |
| 色彩职责 | 主操作用绿，待补证据用琥珀，错误用红；必须同时有文字，不能仅靠颜色 |
| 字体 | Segoe UI / Microsoft YaHei；手记标题可用 Songti / SimSun，禁止网络字体依赖 |
| 字号 | 表格及正文 13–14px，辅助信息 11–12px，页面标题 24–28px；核心数字 40px 左右 |
| 数字 | `font-variant-numeric: tabular-nums`，右对齐、金额固定两位；不要自动滚动计数 |
| 材质 | 主工作表面细边线、低阴影；纸张层次仅用于手记，表格保持平面 |
| 文件夹反馈 | 悬停前盖轻转约 −8°、上移 2px，内页上移约 4px；只作用于 transform |
| 阅读切换 | 正文位移 5px 内，180ms 淡入；连续点击取消旧动画，不能堆叠 |
| 抽屉/提示 | 短入场约 160–220ms，退出更快；焦点进入、Escape 关闭、焦点返回 |
| 减少动态 | 同时尊重系统 reduced-motion 与应用动效开关；保留 Ant 弹出层的可见性与生命周期 |
| 桌面适配 | 1400×860、1100×700 必查；缩放 125%/150% 必查；表格必要时局部横滚 |

禁止用全局 `*` 极短 transition 覆盖 Ant Design 弹窗动画，项目已有跨 WebView2 不可见历史。文件夹效果用 CSS 即可，不引入 GSAP、动画引擎或独立组件平台。

### 交给 Luna 的实施顺序

| 顺序 | 范围 | 完成标准 |
| --- | --- | --- |
| P0 | 先解决 B06 事务归属 | 后端真实连接池失败回滚、并发隔离及关键业务原子性测试通过 |

每个 UI 步骤先做一个完整页面，再复用现有主题和组件推广。不要整库替换 Ant Design，不重做路由或状态管理，不因文件夹造型引入数据库迁移。实施者应同步更新 AGENTS.md 的重要变更说明。
