## 建议优先完善的体验问题

这些发现来自代码复核，本轮没有进行真实窗口点击验收。建议作为一个小批次处理，不必再扩展 runtime 架构。

### 1. 多轮任务完成后，旧轮次仍可能显示处理中（P2）

位置：`src/components/AiPanel.tsx:708-710`、`:839`。

每次 onRoundStart 都新增 running 的轮次卡，任务结束时只更新 currentRound。第 1、2 轮可能已经结束，却留在 running。用户会无法判断“还在处理还是已经做完”。

改法：新轮开始时结束上一轮；完成、失败、取消统一收口本任务未结束的轮次状态。用三轮工具任务验证，不只检查最后一轮。

### 2. 编辑托管配置会顺带改掉外部服务地址（P2）

位置：`src/components/LocalBackendSettings.tsx` 的 persistServer。

当前任何托管配置输入失焦都会调用 persistServer；只要 baseUrl 是 localhost/127.0.0.1 加端口，就将它改成 serverConfig.port。用户原本连接外部已启动的 8081 服务，仅填写备用 GGUF 路径，也可能被切回默认 8080。

改法：只在明确启动托管服务、或编辑当前托管端口时同步连接地址。不要因模型路径、线程等输入失焦而改变外部端点。验证外部 8081 与托管 8080 共存。

### 3. 大模型加载的等待和停止状态不够可靠（P2）

位置：LocalBackendSettings 的 manageServer 和启动/停止按钮。

当前最多尝试 30 次、间隔 1 秒；单次请求耗时另计，并不是可靠的“30 秒总超时”。若 27B 仍在加载，会显示失败而进程可能继续运行；启动等待中“停止”按钮也绑定 loading，Ant Design 会阻止点击。

改法：区分加载中、进程已退出、服务就绪和等待超时；等待时保留可用的取消/停止入口，超时不自动认定模型不支持。健康检查应绑定本次进程/端点，实际加载耗时在公司机测量。

### 4. 温度显示和模型默认值可能不一致（P2）

位置：LocalBackendSettings 的 modelOptions 初始化及 loadModelOptions 合并；`src/localBackend.ts` 的 buildLocalChatBody。

未保存温度时，请求构建器可能按模型/思考状态使用默认值，界面却显示 0.3；切换模型时又用 `options.temperature ?? current.temperature` 保留上一个模型的显示值。用户仅调整输出上限或保留思考时，保存整个对象会顺带把该温度写入新模型配置。

改法：未覆盖温度时明确显示“模型默认”，切换模型按新模型设置重置；只持久化显式覆盖值。设置页应能看到本次生效参数，避免用户以为仅改了一个选项。

### 5. 旧探针结果可能回填到新模型界面（P2）

位置：LocalBackendSettings 的 runProbe 与后端/模型选择。

当前取消后重试的 controller 清理已改进；但自检期间仍能切换模型/地址，旧 Promise 完成后直接 setCapability，会把旧端点结果显示在新选择下。

改法：切换配置时取消探针，或将结果与启动时的 backend/base/model/controller 比对后再展示。能力标签和导出诊断应标明对应的模型，不能混用。

## 性能与易用性，建议实测后再做

- **GPU 使用提示**：默认 GPU 层数仍为 0；在设置页明确其含义，并从实际日志报告卸载情况。不能把“服务可用”当作已经使用 GPU，也不宜不看显存就自动满卸载。
- **避免无意义往返**：目前长结果读取的边界已成立，下一步用真实 27B 记录简单查询、报价比较、导出各自模型轮数、首 token 和总耗时，再判断是否需调整预加载工具。不要继续凭小模型表现增加硬编码禁令。
- **结果文件读取成本**：当前每次续读都读取完整文件并 split。对现有样例可接受，遇到实际大文件耗时显著再改后端分段读取，不提前加缓存体系。
- **样例覆盖范围说明**：450 行样例已走实际文件适配器和 read，但比较/导出核对仍是确定性样例逻辑，不代表模型自主选工具、真实报价业务和数据库写入也通过。界面可直接写“文件读写与分页验收”，把工具协议探针与真实业务试用分开说明。

## 公司电脑下一步验收（只用 UI）

1. 在独立目录配置实际 GGUF、llama-server 和必要的 mmproj，核对模型/上下文/视觉能力及 GPU 卸载。不要带开发机正式数据库。
2. 运行工具链自检和独立文件样例，记录耗时及诊断；任何失败保留错误与日志。
3. 用脱敏报价副本完成“读取→找尾部异常→比较→导出”，检查导出数值和行数，而不是只看模型说完成。
4. 执行中补充口径，核对最终采用新要求；拒绝数据库写入确认，验证没有写入。
5. 对测试数据执行一次授权写入，再检查取消/断流/重启恢复不重复写。此项仍需独立临时数据源，不能拿正式库练习。

本轮没有重新运行 4B HTTP 烟测，也没有公司 27B/视觉/桌面实际数据流程的新结果。建议先收口上述设置和状态问题，再带着明确边界进入实机试用；无需因这些 P2 项重做已经通过的长结果设计。

## 第五轮 P2 修复复核

已完成本轮建议的代码收口：

- AiPanel 在新轮开始时结束旧轮，并在完成、失败、取消时统一关闭仍为 running 的轮次卡片。
- 托管配置只有明确启动服务或编辑端口时同步 loopback 地址，编辑模型路径、线程等不会改写外部服务端点。
- llama.cpp 启动使用 3 分钟总等待期限，期间持续检查进程；区分服务就绪、进程退出和仍在加载的超时状态，停止按钮在加载期间保持可用。
- 温度未显式设置时界面显示“模型默认”，请求不发送 temperature；切换模型会重置为新模型的显式配置，保存其它选项不会凭空写入温度。
- 工具链探针按 backend、地址、模型的配置代次校验；切换配置会取消旧探针并丢弃迟到结果。

复核结果：`npm test -- --run` 为 **378 通过、2 跳过；66 个文件**；`npm run tauri build` 通过并重新生成 EXE、MSI、NSIS。未新增真实 4B HTTP 烟测或公司 27B 桌面验收结果。
