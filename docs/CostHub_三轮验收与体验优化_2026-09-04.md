## P1-01：C1 仍未绑定实际外发文本

位置：`src-tauri/src/lib.rs` 的 `validate_cloud_request`、`validate_cloud_request_with_grant_at_path`。

本轮新增的真实 Rust 反例：同一张合法 C1 授权，material 为 `MLCC`、question 为“公开行情”、端点为 `https://google.serper.dev/search`、方法为 POST。

```json
{"q":"MLCC 公开行情"}
```

合法请求通过后，将正文改成以下**完全虚构的未审批文本**，后端仍返回 Ok：

```json
{"q":"MLCC COSTHUB_DUMMY_SECRET 123.45"}
```

原因：授权 hash 对应审批主题字段，不对应实际正文；正文只检查字段名白名单、少量禁词、是否包含 material/category。允许字段里的额外内容没有与批准内容绑定。GET 查询参数存在同类边界；非 JSON 正文还可能绕开对象字段检查。此结果证明网关校验缺口，**不表示已发生真实泄露**。

最小修复方向：复用现有网关，在可信后端用批准的公开主题/公开型号生成受控检索请求，或者校验实际正文/查询的规范化内容与批准范围一致。固定参数可以由适配器生成；自由文本追加必须重新审查。不能靠继续堆禁词或全面禁止数字解决，也不应让每个安全分页请求都重新人工审批。C1_PUBLIC_MODEL 需同样约束；公开型号可发不等于其伴随内部报价可发。授权签发与授权记录的可写边界也需复核，不能仅把前端写入的 reviewed 或 SQL 行当成不可伪造的批准。

验收：合法 C1/C1_PUBLIC_MODEL 查询通过；已批准内容后追加虚构项目标记/金额、改正文、改查询、非预期正文结构、额外可携带数据的请求字段均被后端拒绝；C2 既有负例保持通过。审计显示实际外发内容。离线测试即可，不使用正式数据验证外发。

现成回归：`src-tauri/src/review_round3_test.rs`，已通过 `#[cfg(test)]` 接入 lib.rs。当前按安全预期断言拒绝，因此会失败；请修实现，不要删除或倒转断言。

## P1-03：阶段成本包的数值、来源与成果状态未闭环

位置：`src/components/CostPackageButton.tsx:17`、`:34`、`:39`、`:49`、`:84`；`src/db/artifacts.ts:72` 起。

已复现的数字错误：

| 虚构输入 | 当前输出 | 正确结果 |
|---|---|---|
| 同名同型号两行：上代 10+20，当前 12+28 | 成本桥净变动 +8 | +10，必须与两个总额之差一致 |
| 历史 cost 列为 5、part_cost 为 5、数量 4 | 行金额 5 | 20，与 BOM 页面口径一致 |
| 数据库返回真实空 BOM，旧 props 仍有金额 30 | 导出金额 30 | 空 BOM/0，并提示数据不足 |

根因分别是：Map 以名称/型号/规格为键覆盖重复行；lineTotal 将旧 cost 列当小计且用 truthy 回退；用数组是否非空代替数据库读取成功与否。

代码确认的来源缺陷：

- 导出写入的 data_fingerprint 是 JSON 字符串，成果库比较的是另一份对象的 8 位 FNV hash。正常读到当前数据时，新生成成果也会立即被判为 stale。
- 导出指纹的 source 只有版本和行数等元信息，未包含草稿实际金额、规格等内容；读写必须共用同一种来源快照与指纹规则。
- 虽然提示“重新读取项目、措施、评审”，实际仍使用 project/measures/reviews props。目标章节也只有目标，没有实际与差额。
- 显式参考项目没有冻结版时会回退到本项目旧版本，但仍可能标记上代项目名称；规格又读取参考项目实时值，并不保证与冻结 BOM 同一版本。
- phase_cost_package 未被成果分类函数识别为 project/project_cost，项目归属读取也没有使用其 data.projectId；应归入已有项目成果分类，不新增独立成果库。

最小修复方向：复用已有 BOM 单价/数量函数并核对其适用字段，明确 frozen line_total 与 draft unit×qty；匹配时先聚合重复键，或用能保留完整行的映射，不把缺失映射当零差异。桥净额必须等于总额之差，Top N 之外有“其他差异”合计。读取失败与真实空数据分开处理，不静默用旧缓存生成正式交付。一次读取一致的导出来源，导出与成果新鲜度共用指纹；明确旧上代缺失/规格不在同版的缺口。

验收：表中三项通过；新成果显示当前/草稿而非无故过期；任一实际来源变更后正确过期；上代总额、当前总额、桥净额、领域汇总相互对账；前一代未冻结时不得借本项目旧版冒充；导出的措施/评审来自最新数据库；成果位于正确项目分类。
