# CostHub AI 协作界面与审批可视化改造方案

日期：2026-09-20  
设计与验收负责人：Astra  
实施：Luna  
交付范围：界面、决策路径、过程折叠、对话内审批、完整外发内容与本地敏感提示；移除右侧结果画布、恢复时定位最新消息、简化技术选项、统一文件保存位置。

## 1. 本次必须达成的五个结果

1. AI 协作窗清爽，以 ChatGPT 式对话层级为交互参考：内容优先、单一输入区、少量常驻按钮。沿用 CostHub 配色和主题，不复刻品牌，也不声称与 ChatGPT 内部机制相同。
2. 信息判断路径可视化，每个节点可查看输入来源、判断依据、结果、下一步；未执行的节点不能显示通过。
3. 工具、推理摘要、请求与上下文处理过程默认收起，用户随时展开，正文不被日志淹没。
4. 对话产生的审批在对应对话中出现并完成，审批卡片不可随工具过程一起折叠，不需要到设置、底部横幅或另一页面寻找。
5. 审批时默认展示实际将外发的完整提示词/业务请求内容，不截断、不以摘要替代；本地识别的疑似敏感词高亮，并能查看依据。

补充需求见第 13 节，同属本轮交付，优先于前文中与其冲突的旧安排。

本轮只改这些体验和必要的流程连接，不引入自动多 Agent 调度、不重写 Pi、不替换数据库、不放宽外发权限。没有自动切换云端能力的路径不得通过界面暗示已经实现。

## 3. 界面设计定稿

```text

│──────────────────────────────────────────────│
│                       用户的问题             │
│                                              │
│ 助手正文：结论、依据、可操作建议               │
│                                              │
│ ▸ 执行过程 · 3 个工具 · 1 次判断 · 已完成      │
│                                              │
│ ┌ 等待你确认 · 本轮暂停 ───────────────────┐ │
│ │ 用途、云端服务、发送目的地                │ │
│ │ 检查结果：2 处需核对                      │ │
│ │                                          │ │
│ │ 完整待发送内容（默认可见，可滚动）        │ │
│ │ [system] …完整文本…                      │ │

│ │                                          │ │

│                                              │
```

这里只是结构示意。正式界面使用组件和主题变量，不能把示意图当成静态图片嵌入应用。

### 3.2 常驻操作与收纳

- 顶栏：标题、模型简称/本地云端状态、新对话、更多。模型名称可点开选择器，不另外占一整行。
- 更多菜单：历史对话、展开/收起协作窗、连接与模型设置、执行模式、脚本权限等低频操作。保留原有授权，不把脚本开关伪装成无风险普通设置。
- 输入区：多行输入框、附件、发送/停止。发送与停止互斥；执行时补充指令沿用原能力，通过说明提示，不新增一排常驻按钮。
- 深度思考移到模型设置小面板；状态需要体现时放在模型名称旁的轻量文字内。
- 上下文用量、工具统计、数据就绪度收进执行过程/详情，不常驻大段技术文字。
- 路径入口归属每轮执行过程，保留查看历史能力；不再在多个位置重复显示同一条路由和计数。
- 待审批时即使工具过程已折叠，也必须独立显示审批卡片。协作窗折叠时显示待审批数量，点击展开并定位该卡。

### 3.3 视觉规范

- 沿用当前主题变量，浅/深色都要实现；不得新写一套全局硬编码白底主题。
- 助手正文直接排在对话背景上；用户消息用轻微底色；卡片主要留给审批、图表和明确结果。
- 内容区域保持实色或近实色，玻璃通透感仅用于外层边界；文字不叠重模糊，不给选中文字加滤镜。
- 正文 14px、行高约 1.65；辅助信息 12px；正文段间 10–12px，消息间 20–24px。字体沿用应用现有无衬线系统。
- 常规圆角 10–12px；输入区 16px；1px 细边框；取消高饱和装饰渐变和多层阴影。
- 状态：蓝=处理中，绿=已确认，琥珀=需要核对，红=阻断/失败，灰=未运行。配文字/图标，不靠颜色单独表达。
- 输入区吸底但不遮消息；宽屏正文居中并限制约 760px；窄侧栏 320–420px 可读，无横向整页滚动。长 URL、提示词和型号自动换行。
- 节点展开使用轻微动效即可，遵守现有关闭动效和系统 reduced-motion。无需动效库或新 UI 依赖。

## 4. 执行过程：一轮一个可折叠容器

默认只显示一行，例如：

> 执行过程 · 已完成 3 项 · 用时 8 秒

执行中更新为实际状态，例如“正在查询 BOM”“等待你批准发送”，不可编造计划或进度百分比。工具数量和耗时来自真实事件。

展开顺序：

1. 判断路径。
2. 工具列表：名称、状态、耗时；点开再看参数、结果摘要和完整结果入口。
3. 上下文整理：实际预算/估算标识、纳入与排除、压缩前后、证据来源。
4. 网络请求：目标、审批 ID、requestId、准备/尝试/确认发送/未知/失败/取消。

默认折叠所有细项。成功工具不用逐个生成独立大卡片。大 BOM 仍使用本地结果引用，不为了界面回放把全文重新喂模型。

错误可以在摘要行显示简短原因；审批不能藏在容器中。面向用户展示可验证的操作与依据，不要求输出模型逐字内部思维链。若保留已有模型思考内容，单独标明模型输出、默认折叠，不能当作审计事实。

## 5. 判断路径：节点、分支与详情

```text
收集上下文 → 来源归属 → 本地敏感检查 → 路由决定
                                  ├─ 本地处理 → 执行 → 结果
                                  ├─ 不确定 → 留本地 / 请求澄清
                                  └─ 云端候选 → 构建公开内容 → 用户审批
                                                        ├─ 拒绝 → 留本地/结束
                                                        └─ 批准 → 后端复核 → 发送 → 结果
```

所有图形由真实事件驱动。默认纵向适配侧栏，宽屏可以横向；节点使用普通 DOM/CSS 即可，无需拖拽画布。路径是审计记录，不能提供用户拖线改变安全顺序的功能。

每个节点展开至少展示：

| 字段 | 要求 |
|---|---|
| 状态 | 未执行、进行中、通过、阻断、需确认、失败、取消；不得把没有事件当通过 |
| 输入来源 | 项目/消息/文件/工具结果的稳定 ID 与可点击来源，不只显示当前全局状态 |
| 判断执行者 | 宿主规则、后端校验、本地模型、用户；禁止把规则检查写成模型审查 |
| 判断依据 | 命中的具体规则/本地模型标注与置信度/用户选择；没有依据时写未记录 |
| 结果 | PUBLIC、SENSITIVE、UNKNOWN 或相应业务结果，用中文解释 |
| 下一步 | 实际进入的分支；未选分支灰显 |
| 关联标识 | runId、requestId、审批记录、载荷版本，技术标识默认收在详情 |

规则提前阻断时后续模型检查显示“未执行：已由来源规则阻断”。CloudSafe 仍靠用户手动选择的情况必须标“用户选择云端候选”，不能写“本地模型决定转交云端”。

历史展示使用该轮快照，不能套用当前 WorkingState。旧版本缺节点/来源时显示“旧记录未保存此信息”；解析或读取失败单独显示。沿用已有游标分页，不通过固定前 N 条假装完整。

## 6. 审批必须是对话流程的一部分

### 6.1 请求归属与定位

- 每条审批绑定 sessionId、runId、对应助手消息、requestId/稳定待发送请求 ID、载荷版本和来源类型。
- 对话请求只出现在对应会话。后台任务有独立入口；全局通知只能导航到对应审批，不能把所有后台请求塞进当前对话。
- 收到真实待审批事件即插入卡片，不能依赖模型正文含“审批”两个字才展示。模型声称待审批但没有真实请求时，显示“尚未生成待审批请求”，不给虚假的批准按钮。
- 卡片首次出现时：用户在消息底部就滚动到卡片；用户正在阅读旧消息时显示“有待审批请求 · 查看”，点击定位，避免强抢滚动。
- 切换任务、收起再展开、程序重启后仍能看到待审批状态。持久化审批元数据与本地载荷引用；重启后重新校验授权，不静默执行。

### 6.2 审批卡片状态

```text
准备内容 → 本地检查 → 等待用户 → 写入授权 → 后端复核 → 发送中 → 完成
                        ├─ 拒绝 → 不发送
                        ├─ 修改 → 旧版本失效 → 重新检查/审批
                        └─ 取消/过期 → 不发送，需再次确认
```

- 卡片标题：“需要你批准云端发送”。说明这次为何需要云端、发给谁、发什么。
- 常驻操作仅“批准本次发送”“拒绝”，次级“修改内容”。不要默认提供“全部批准”“以后都允许”。
- 用户批准后只恢复该 requestId 对应的等待动作，不能重放整轮工具、业务写入或整个 pendingRetry 队列。
- 一张审批卡默认一次发送；重试及回退到另一个供应商必须有明确的授权覆盖规则，不能悄悄借用。
- 网络关闭、内容硬阻断、日志/授权保存失败时，不显示可发送的假成功状态。
- 重复点击、回车连按、重复事件不造成重复发送。执行期间禁用按钮，结果后保留只读审批记录。
- “拒绝本次”仅作用本次，不偷偷转成 30 天忽略。若业务仍需要长期忽略，放在独立选项并明确期限。
- “修改内容”只编辑候选外发副本，不改原聊天/业务数据；保存修改后重建载荷、重新本地检查、刷新版本和哈希。
- 取消保持现有 Rust requestId 取消链；已经发送的数据不可撤回，发送未知不能显示未发送。

### 6.3 合并重复确认

当前 CloudSafe 可能先“确认公开文字”再批准请求体。合并成一张最终审批卡：其中明确说明“批准表示同意把下方完整内容发送到指定服务”。候选内容在批准前仅供本地审阅，不能因为为了预览就标记 verified=true 并获得发送权限。

内容检查和用户授权是不同状态。用户允许发送不自动把来源判定改为公开；明确的敏感硬阻断不能靠点批准绕过。UNKNOWN 不得被程序默认为 PUBLIC；需要可靠来源或明确的审阅过程解决其分类，不符合当前政策就留本地。

## 7. 完整外发提示词：明确什么是“完整”

**审批看到的必须是这次实际准备发送的完整业务内容，批准后发送的必须是同一版本。**

包括实际存在的 system/developer/user/assistant 消息、检索内容、结构化状态、工具描述或结果，以及搜索请求的完整业务字段。当前 CloudSafe 应保持 tools=[]，显示“本次不发送工具”，不能为了展示去补造工具或历史。

- 用清晰的角色分区展示正文；默认展开，允许卡片内部滚动、搜索、复制全部、放大阅读。滚动不等于省略，内容必须全部可达。
- 不使用省略号、前 1000 字、摘要代替正文，也不默认将正文藏进 details。复制得到的内容必须完整。
- 显示全文字符数、消息数；token 若为估算须写“估算”。没有读取到全文时禁止批准，不能拿摘要审批后发全文。
- 多段/多个请求分别列出，明确每次去向。搜索与云端模型是不同请求，不能只给用户看搜索词却后续发送其他提示词。
- 单独提供“实际业务请求 JSON”视图，包含模型、完整消息及相关业务参数；审批哈希复用现有后端规范，最终请求体有任何业务内容变化必须重新审批。
- API Key、Authorization、供应商密钥属于传输凭据，不是提示词。只显示“由后端注入凭据”，不得为了“完整”把密钥展示、复制或写入审计正文。
- 对非文本附件：如本轮不支持就明确拒绝/保持本地；若将来允许，需独立列出实际附件与处理方式，不能隐藏在“文本已审查”之下。

### 7.1 处理现有截断

`cloudContext.ts` 的 clip 当前截到 2400 字并合并空白。Luna 必须检查所有最终载荷构造点：

1. 不得在审批后截断、改写、追加内容。
2. 用户要求全文发送且超出限额时，清楚告知限制并阻止该请求，允许用户主动编辑或明确分批；不能暗中只发前 2400 字。
3. 如业务本来就只需要摘要/脱敏投影，明确显示被排除的来源与原因；审批区仍显示投影的完整实际正文，而不是该投影的再次摘要。
4. UI 的可视区域高度不影响实际内容，不能通过展示截断来省渲染成本。达到应用大小限制时明确拒绝，不绕过限制。

## 8. 疑似敏感词高亮：本地、可解释、不改原文

规则检测继续作为安全底线；用户提出的“模型觉得可能敏感”由**本地模型**可选补充，绝不能先把内容发给云端检测。

- 高亮放在审批的完整正文中，不只列一张旁边的词表。
- 红色/标记“阻断”：明确不允许外发的规则或来源。不能靠按钮覆盖后端禁令。
- 琥珀色/标记“需核对”：本地模型提出的潜在风险，例如未发布产品名、内部代号、报价相关信息、客户身份；同时显示“模型提示，可能误判”。
- 无命中只表示“未发现命中”，不能显示“保证安全”。模型检查未启用、失败、超时或未运行，必须明确显示。
- 点击/键盘聚焦标记可看：原片段、风险类型、依据、来自规则还是本地模型、所在消息/来源。可用上一个/下一个风险定位。
- 本地模型只返回结构化标注：消息 ID、精确原文引用、起止位置、风险类型、简短理由与置信度。宿主校验范围和引文一致后再高亮；无效标注不能任意标错文字，应显示“标注无法定位”。
- 中文、emoji、重复词、重叠区间要有一致索引约定并测试。重叠标注合并展示，不丢失其依据。
- 使用 React 文本节点与 `<mark>`，禁止将模型返回 HTML 直接注入；含 `<script>` 的输入也只能作为文本显示。
- 高亮是一层显示标记，不改变字符、空白或换行，不改变已审批哈希和复制内容。
- 本地审查依据 payloadHash 缓存同一版本结果，文字不变不用每次重跑；修改/模型策略变化后失效。硬规则可提前拒绝，无需每次让 27B 再思考一遍。
- 本地语义检查只产出风险提示，不得把模型的 PUBLIC 当成不可推翻的安全凭据。失败时保持既有 fail-closed 原则。

## 9. 最小实现路线与数据约束

优先复用现有 session/run/request 标识、Gateway 事件、审批票据、检查点和后端授权。只补现有缺的字段，避免再造第二套审计表和授权状态机。

需要能表达的最小关系：

```text
session → run → assistant message → outbound request/version
                                  ├─ exact local payload reference + hash
                                  ├─ source IDs / included & excluded IDs
                                  ├─ local findings + check status
                                  ├─ user decision + approval grant
                                  └─ transport events + outcome
```

- 正文存本地、事件存引用和必要元数据；完整提示词不进入外部遥测或通用错误日志。
- 同一个 requestId 的重复事件幂等更新；不同请求不能因为物料同名就合并审批。
- 来源沿用稳定 message.id，在当前会话内跨运行定位；历史判断使用历史快照。
- 页面组件可拆分为消息、折叠过程、判断路径、审批卡片，复用现有文件优先。不要引入全局状态库或节点图框架。
- 本地脚本权限、业务写入确认和云端发送批准是不同权限；可以共用卡片视觉，但不能共用授权票据。

## 10. 给 Luna 的实施顺序

### A. 先打通审批归属和完整载荷

逐个检查对话云端工具、CloudSafe 主请求、C2、后台队列的实际调用者。明确 requestId 与 session/run/message 归属；只恢复批准的请求；完整预览与实际发送绑定。优先解决“有审批但找不到”。

### B. 收口主界面与折叠过程

按第 3、4 节移走低频按钮，保留全部原功能入口。审批独立于折叠过程。不要为了简洁删除来源、工具结果或权限状态。

### C. 节点路径与敏感标注

复用真实事件绘图，补各节点原因和未执行状态；接本地标注及宿主校验；完整内容默认可见。禁止用固定演示节点冒充运行事件。

### D. 验证与交付

完成下面的验收矩阵后再打包。提交修改清单、测试结果、合成场景截图/录屏与未验证边界。更新 AGENTS.md。没有真实模型测试就明确写未测，不能用 mock 通过宣称实机体验完成。

## 12. 完成定义

用户在一条真实对话里能直接看见：正在做什么、为什么留本地或提出外发、每个判断节点如何得出结果、完整将发内容与疑似敏感位置；能在原位置批准/拒绝并正确继续；全过程可折叠且事后可回放。

只有界面截图、节点名称、后台日志、弹窗卡片、模拟模型回复或全部单元测试通过，均不能单独代表上述完整流程已交付。

## 13. 用户补充：单一对话、最新位置和统一文件位置

### 13.1 删除右侧结果画布

- 移除 AI 对话旁边单独的结果画布/第二栏，不仅是默认隐藏。全屏也采用单一对话列，不再自动切换为左右分屏。
- 图表、表格、报告摘要及生成文件卡片直接插入产生它们的助手消息；与结论、来源、计算口径保持在同一条消息内。
- 图表保留放大、查看数据、导出；大表默认显示有标识的预览和完整文件入口，不能为取消画布而删除功能。
- 单个图表可以临时放大阅读，关闭后回到原消息；不因此恢复常驻侧画布。
- 历史消息的图表和文件继续可打开，不能只把最新结果搬进对话而丢历史。
- 删除无用画布状态、重复结果渲染和两栏样式，避免同一图表渲染两份。
- 此处删除的是独立结果画布，不是删除 AI 协作入口或主对话本身。

### 13.2 重新进入默认定位最新消息

- 离开页面后回来、收起再展开、重新打开应用恢复会话、从历史列表进入一个会话：默认定位该会话最新消息，不停在开头或上次阅读的旧位置。
- 等历史消息、图表和附件布局完成后再稳定定位底部，不能仅在请求开始前执行一次 scrollTop。
- 正在阅读旧消息时不能被每个流式 token 强行拉回底部；显示“回到最新”。用户回到底部后才恢复跟随。
- 滚动容器只管理对话区域，不带动整个应用页面；定位到来源原文等显式用户操作可以暂时覆盖默认底部定位。
- 历史加载前显示加载状态，不先滚动空列表再跳到顶部；连续切换会话用请求序号/取消机制防旧请求覆盖新会话。
- 待审批卡位于对应消息，进入时优先遵守最新位置；如最新位置看不到未处理审批，提供“有待审批 · 查看”定位入口，不能弹出另一个审批窗口。

### 13.3 不再常驻“原生工具”“Local”“打开任务目录”

- 原生工具模式作为默认执行方式，旧模型兼容入口仅放到设置的高级区域，使用中文解释何时需要，不要求普通用户理解协议。
- 移除对话底部 Local/CloudSafe 路由选择器。默认由本地模型处理；已有云端工具仍按审批调用。
- 当前未具备任意任务自动委派云端主模型的能力，不得因为隐藏选择器就宣称已支持。若保留手动 CloudSafe，放到更多菜单中，命名“使用云端处理公开问题”，并解释只发送本次批准内容。
- 顶部允许保留轻量“本地模型 · 模型名”状态，这是说明信息，不再占用一个技术选项栏。
- 移除常驻“打开任务目录”。生成文件卡片显示清楚文件名、类型、保存位置，以及“打开文件”“在文件夹中显示”；已有文件才能展示可用操作。
- 统一使用“文件保存位置”或“AI 工作文件夹”等用户能理解的名称。运行目录、沙箱和执行协议只出现在需要的高级说明中。

### 13.4 文件保存位置：默认 EXE 所在文件夹

**默认用户工作文件夹为正在运行的 EXE 所在文件夹；最终生成文件直接保存到这个选定文件夹。** 不擅自改成用户目录、临时目录或用户找不到的随机任务文件夹。

在设置中新增或复用“AI 工作文件夹”：

- 显示完整解析路径；提供“选择文件夹”“恢复默认（程序所在文件夹）”“打开文件夹”。
- 默认值保存为“跟随程序目录”的策略，不把开发机的绝对路径打包给同事。exe 移动到另一目录后，默认策略随程序解析。
- 自定义目录持久化；需要为便携部署标识路径类型，外机无效时明确提示，不静默写到另一个目录。
- 保存时检测实际目录存在、可写；默认目录不可写时显示原因并引导选择，不能悄悄写入系统目录或报告导出成功。
- 修改设置只影响后续新任务的目标位置；运行中任务固定使用启动时解析的路径。历史文件仍按原记录打开，不自动搬家或删除。
- 每个生成文件在对话中显示实际保存位置，导出成功以写入成功为准；失败保留任务结果和可重试入口。
- 同名文件默认生成不冲突名称；明确覆盖需要用户操作，不可静默覆盖原文件。

### 13.5 不把 EXE 目录变成 AI 的任意写入权限

“文件保存位置在 EXE 旁边”和“赋予脚本对整个程序目录任意读写”是两回事。用户要求简化文件位置，不是取消此前安全边界。

- 最终交付产物落到选定工作文件夹；脚本执行、临时附件、完整工具结果等内部工作仍使用现有隔离任务目录，可在工作文件夹内维护内部子目录，或继续使用满足 AppContainer 要求的隔离位置。
- 宿主通过现有文件/导出能力将选定产物安全落到用户工作文件夹；不要给模型任意目标绝对路径参数，后端根据已保存配置解析目标。
- EXE、正式数据库及其 WAL/SHM、密钥、配置、运行日志和其他系统文件不得作为 AI 产物覆盖目标；目录穿越、junction/symlink 越界继续拒绝。
- 不因为目标目录相同就开放模型读取整个程序目录或其他任务文件；只开放当前任务明确提供的附件和结果。
- 文件卡的路径是最终用户产物路径，不是假称临时任务文件已经导出。若采用复制落盘，复制失败要明确显示。
- `src/ai/piExecution.ts`、Rust 工作区/文件命令、`write_excel`、报告与图表导出等调用者一并检查，不可只改一个“打开目录”按钮。

### 13.6 本轮补充验收

| 场景 | 通过要求 |
|---|---|
| 普通/全屏 AI 对话 | 无右侧独立画布，图表和结论在同一消息内，历史图表可查看 |
| 展开大图后返回 | 返回原消息，不切换为第二栏，不丢阅读位置 |
| 退出后重新进入、程序重启 | 消息和图表布局完成后稳定处于最新位置 |
| 阅读旧消息时继续生成 | 不抢滚动；回到最新后正常跟随 |
| 默认配置复制 EXE 到新目录 | 新任务生成文件落在新 EXE 目录，而非开发机目录 |
| 自定义工作文件夹 | 之后的新任务产物保存到选定目录，文件卡可打开对应文件 |
| 目录只读/失效/磁盘写失败 | 明确失败或要求选择位置，不静默换目录、不报告假成功 |

| 普通对话底部 | 没有原生工具/Local/打开任务目录常驻按钮，低频能力仍有明确入口 |
