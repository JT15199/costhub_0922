# CostHub 原生 Pi 能力接入方案

日期：2026-09-07。状态：核心执行链已落地；真实 Ollama/Tauri/干净 Windows 的人工验收仍需执行。

## 目标与范围

用户希望内置 AI 具备接近原生 Pi 的通用工作方式：理解任务，自行读取文件、加载 Skills、编写和运行脚本、查看结果、修正错误，并持续完成任务；同时保留 CostHub 的成本业务能力。

本方案取代 `CostHub_Pi_Agent_Runtime_实施方案.md` 中“不启用文件、Shell 和扩展发现”的旧范围限制。用户已经明确扩大目标。优先沿用当前 Pi Agent 和 Tauri，先不引入第二套 Agent、Node sidecar、技能商店或多 Agent 调度。

代表性任务：“读取这个目录中三家供应商的报价，识别表头，统一税率和币种口径，找出可比项目，生成带来源的对比 Excel 和谈判备忘录；确认后导入项目。”不同表格结构应由 Agent 结合工具和脚本处理，而非只能走事先写死的模板。

## 已核实的基础与缺口

当前安装 `@earendil-works/pi-agent-core` 和 `pi-ai` 0.84.4。

| 位置 | 当前情况 | 实施方向 |
|---|---|---|
| `src/ai/piRuntime.ts` | 使用真实 `Agent`；每次请求重新建立、主要恢复用户和助手文本 | 按会话保留 Agent，恢复完整消息和工具结果 |
| `src/ai/piStream.ts` | 通过现有 Tauri/Ollama 链路完成原生工具调用 | 继续复用，支持文件工具返回的结构化内容；模型能力不足时明确展示 |
| `src/ai/toolSelection.ts` | 关键词与页面预选业务工具 | 通用文件和执行工具不受业务关键词限制；业务工具仍可精简选择 |
| `src/aiSkills.ts`、`src/ai/skills/registry.ts` | 两套业务技能描述，未形成标准目录加载 | 接入标准 Skills；整理旧定义，避免第三套重复注册表 |
| `src/components/AiPanel.tsx` | 有停止、确认及事件展示 | 增加执行中补充指令、排队任务、命令输出和产物入口 |
| `src/ai/orchestrator.ts`、`src/autoThink.ts` | 后台仍用旧循环 | 后续复用同一运行入口，但后台不继承交互会话的通用执行授权 |

重要版本陷阱：依赖虽导出 `AgentHarness`，但本地 `dist/harness/agent-harness.js` 的 `prompt`、`resume`、`compact` 等方法实际拒绝并报 `HarnessNotImplemented`，恢复也未实现。**不得仅凭类型声明迁移到它。** 继续使用已经运行的 `Agent`。

该版本的 `loadSkills`、`createReadTool`、`createWriteTool`、`createEditTool` 和 `createBashTool` 有实现。文件工具执行函数需要第五个参数 `{ env }`；接入普通 Agent 时薄封装绑定环境，不复制工具算法。`Agent` 本身已有 steer、followUp 和 abort。

## 最小可行架构

```text
CostHub AI 面板：任务、执行轨迹、补充指令、产物
                 ↓
现有 Pi Agent + 原生工具协议 + 会话记录
   ├─ CostHub 业务工具 → 既有校验、确认、事务、证据与审计
   ├─ Skills 元数据 → 按需读取 SKILL.md、参考文件和脚本
   └─ 文件 / 命令工具 → Tauri Rust → 任务工作目录、进程和产物
                 ↓
现有本地 Ollama 模型链路
```

在现有运行模块附近添加一个 Tauri ExecutionEnv 适配模块，Rust 负责真实文件与进程操作。按依赖的 `FileSystem`/`Shell` 合约映射错误、路径、字节和取消；不支持的方法返回明确的 `not_supported`，不得假装成功。原生文件工具复用读取分页、精确编辑和输出截断行为。

Windows 默认提供名称和参数描述准确的 PowerShell 命令工具。只有真实检测到 Bash 时才挂载原生 `createBashTool`；不能把 Bash 指令悄悄送进 PowerShell。目录列举和搜索先通过命令完成，不先造工具大全。WebView 不直接导入 `/node` 或调用 Node 内置模块。

Python、Node、Git Bash 及文档处理库是实际运行依赖，Skills 不会附带这些能力。先检测可执行路径和版本，显示缺少项；不默默下载或安装。内置技能优先选择已有运行环境能够执行的版本。最终在没有开发环境的 Windows 机器验证分发与依赖提示，不能只测开发电脑。

## 工作目录、权限与数据

默认使用独立任务目录，附件复制进去，生成文件放在其中，界面显示真实目录与运行环境。普通读写工具在后端检查规范化路径、父目录及 Windows junction/symlink，写入使用可恢复或原子替换策略。

**工作目录不是 Shell 沙箱。** Pi 官方明确不自带文件、进程、网络或凭据权限隔离。开放本机任意命令后，脚本可能访问目录外文件、数据库和网络；禁止路径字符串、提示词或限制 cwd 都不能解决这一点。

首版采用用户明确启用的“本机执行”模式：说明实际进程权限，对已授权任务内的普通操作持续执行，避免每次读取都询问。破坏性操作与正式业务数据写入保持明确确认。未启用时仍能用业务工具，但界面不能称为完整执行模式。若产品要求强制禁止外发或保证脚本不能接触正式数据库，则必须先接入经过验证的操作系统隔离；不能在开放本机执行的同时继续显示无条件“数据不会外发”。

Agent 应通过既有业务工具更新正式数据，脚本用于任务文件和分析产物。此规则是工作流程约束，在无系统隔离的本机执行模式下不能宣称是不可绕过的安全边界。已有云端票据与审批链继续保留；它也不能自动约束任意 Shell 网络请求。

命令必须具有执行 ID、默认超时、输出大小限制、stdout/stderr、退出码和取消。Windows 隐藏启动；停止和应用退出需要终止整个子进程树，不能只关闭输出订阅。避免将凭据默认注入执行环境。

## Skills 的接入

使用依赖现成的 `loadSkills(env, dirs)` 读取应用内置目录和用户明确添加的技能目录。系统提示只列名称、用途、路径，需要时由 Agent 读取全文与相对引用文件。用户可显式指定技能，自动选择不依赖中文关键词完全匹配。

不把开发 Codex 的插件缓存当成产品资源。内置的第三方技能应记录来源、固定版本和每个目录的许可证，并验证脚本依赖。Anthropic 的文档技能可作研究候选，但其官方仓库明确将 docx/pdf/pptx/xlsx 标为 source-available，不能按整个仓库的通用开源印象直接打包分发。

先提供一个小型、自有且可执行的“报价文件分析”技能作为贯通样例：读取真实输入、执行脚本、检查输出并返回产物。随后再挑选成熟第三方技能；先不做在线市场、自动更新和任意插件代码热加载。

## 会话和交互

每个会话保留完整 AgentMessage，包括 toolCallId、工具请求、结果和错误；展示摘要与模型历史分开，不能沿用最后 16 条纯文本作为唯一恢复依据。复用现有 SQLite 会话存储，增加必要字段或记录类型即可。

执行中输入提供“立即补充”和“完成后继续”，分别连接 `steer` 和 `followUp`。停止连接 Agent abort 和实际命令取消。刷新/重启恢复已完成记录；处于执行中但结果未落盘的写操作标为结果未知，先核对而非自动重放。业务写入按稳定调用 ID 去重，避免确认后恢复造成重复入库。

长对话保留原始记录，模型上下文使用摘要与近期完整工具轮次。优先验证并复用依赖现成的压缩辅助函数；其模型接口必须接通当前本地传输，不能假定设置一个 compaction 开关就会运行。摘要失败时保留原记录、明确报告上下文不足，不静默遗忘。上下文预算从实际模型配置获取；未知时使用标注为估算的保守值。

界面用折叠执行条展示“正在读取 / 运行脚本 / 检查结果 / 已完成”，可展开命令与错误。最终答案给可打开的产物和来源。保持流光玻璃视觉，不另做一套开发者控制台。模型原生工具能力不足时明确说明可用范围，兼容循环不能伪装成已经实现同等能力。

## 实施与验收顺序

1. **贯通工具执行**：复用 Agent，接入 Tauri 文件环境与 Windows 命令，完成读→编辑→执行→读取结果。先验证当前依赖工厂的实际调用，不升级依赖碰运气。
2. **贯通 Skills**：加载标准目录，以自有报价分析技能完成真实附件任务。修整重复技能配置，保持现有业务工具可用。
3. **贯通会话控制**：完整记录、恢复、steer、followUp、取消和长上下文处理，保留现有写入确认。
4. **桌面验收和收口**：真实本地模型、真实 Tauri、干净 Windows 环境验证；更新 AGENTS.md 与使用说明，记录能力边界。后台入口统一可随后做，后台授权不得跟着扩大。

必须提供最小的可重复集成检查，并留下以下真实运行证据：

- 不含预设触发词的请求能够加载 Skills，读取其相对路径脚本，处理两份结构不同的报价并生成可打开的 Excel/CSV 与备忘录；金额由程序计算且注明口径。
- 脚本首次失败后，Agent 根据真实 stderr 修复并重跑；缺依赖时准确报告，不编造成功。
- 用户途中补充“仅比较含税报价”，后续行为遵守；排队任务不丢失。
- 停止超时脚本后子进程树退出；连续执行时 UI 可响应，大输出截断且全文有可读路径。
- 重启恢复完整工具上下文；确认过的业务写入不重复，结果未知的操作先核对。
- 普通文件工具拒绝越界与 junction 绕过；本机 Shell 模式的权限描述真实，不把 cwd 当隔离。
- 现有 BOM 导入、写入拒绝、云端票据与成本计算检查继续通过。记录实际模型、上下文、耗时与失败案例，不以 Mock 通过代替模型验收。

完成判断：能围绕新任务自主组合工具、使用真实技能资源、产生并核验文件、在失败后继续处理。仅新增一批提示词、工具按钮或在界面写“Pi 原生”不算完成。相同运行机制也不保证小型本地模型拥有与强模型相同的完成质量。
